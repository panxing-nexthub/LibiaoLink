## 3. 0013 → 0014 Schema Diff

### 3.1 项目目录

- `project_read.local_projects` 新增 `deleted_at timestamptz`；软删除后目录读取排除该行。
- 删除旧的本地单表编号唯一约束 `ux_local_projects_code`，改由跨来源 `project_read.project_code_claim` 保证可用编号唯一。
- 重建 `sync_project_code_claim()`：编号可用性统一按 `deleted_at is null and source_missing_at is null` 计算；本地项目更新或软删除时会刷新占用声明。
- `project_read.project_directory` 继续以 `security_invoker = true` 合并核心与本地来源；本地项目返回真实 `deleted_at`，核心项目返回投影中的删除/源缺失时间。
- `project_summary` 未混入本地项目，仍是核心只读投影。

### 3.2 案例

- `case.cases` 新增：
  - `translation_group_id uuid not null`，存量行回填为自身 ID，新行默认 `uuidv7()`。
  - `review_status text not null default 'not_submitted'`，允许 `not_submitted/reviewing/approved/rejected`。
  - `review_ref text`、`archived_at`、`deleted_at`。
- 新增索引：`translation_group_idx`、`project_updated_idx`、`review_status_idx`。
- 新建 `case.case_versions`：保存不可变版本快照、版本号、变更摘要、恢复来源和创建人；为存量案例按当前 `row_version` 回填首个版本。

### 3.3 素材与挂接

- `case.case_asset_uploads` 新增 `project_id`，允许 `case_id` 为空；项目级素材上传不再强制绑定案例。
- `case.case_assets` 新增 `project_id` 与 `asset_version_no`；存量行从案例项目回填，并按同一 `asset_id` 的上传顺序补版本序号。
- 新建 `case.case_asset_metadata`：保存 `assetType`、标题、说明、locale、标签、密级、客户可见/讲解/分享标记和独立 `row_version`。
- 新建 `case.case_asset_links`：同一项目素材可挂接多个案例，主键为 `(asset_id, case_id)`。
- 将 release 素材外键改为精确引用 `(asset_id, asset_version_id, object_version_id)`；历史发布快照不随后续素材版本变化。
- 新增/调整运行角色授权，作者角色可写本地项目、素材元数据、挂接、案例版本和软删除字段，但仍不能写核心库或删除对象版本。

## 6. 回滚

`0014` 是 forward-only，不编写或执行逆向 SQL。回滚以“应用快照 + 数据库快照”恢复整库一致性，避免只回退表结构而保留新代码写入。

1. 停止 `projection` 与 `gateway`，停止新的作者写入。
2. 恢复应用目录 `app-before-0014.tgz` 到 `/opt/libiaolink-case/app`。
3. 由数据库管理员恢复 `libiaolink_case-before-0014.dump` 到 `libiaolink_case`。
4. 恢复旧应用后启动网关与投影，复核四个健康检查和旧版本作者接口。
5. 对象桶中的 `projects/*` 新对象与版本默认保留；如策略造成兼容问题，将旧策略 `libiaolink-case-gateway` 重新挂回父用户，再解绑 v2。
6. 如只回滚应用而不回滚数据库，不得启动依赖旧 schema 的旧网关；必须按快照整体回退或保持新应用运行。

恢复数据库前必须确认目标库和备份文件路径，禁止对正式机执行本测试回滚脚本。
