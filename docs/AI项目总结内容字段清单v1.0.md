# AI 项目总结内容字段清单 v1.0

> 状态：内容口径已确认（2026-11-24）；交付形态、接口与权限待定。
> 适用：单个项目的 AI 项目总结；不含跨项目汇总、年度总结、员工绩效评价。
> 归属：内容与字段口径 px；契约 / 后端采集与抽取 wmj。涉及项目主数据字段、文件类型与契约的改动，先与 wmj 对齐再开工。

## 1. 范围

本文只定义「AI 项目总结要展示哪些内容、每项从哪里取、取不到怎么显示」。

不定义：

- 交付形态（Word / PDF / 页面）；
- 接口路径与请求响应结构；
- 权限位与审批流；
- 模型选型、提示词细节与成本。

以上待内容定稿后另行讨论。

## 2. 统一口径

1. **未识别**：字段在指定来源中确实不存在，或抽取失败 / 冲突，页面统一显示「未识别」，不补写、不推断、不用其他字段替代。
2. **只认原文**：技术协议字段必须来自原文；同一字段出现多个冲突值时判为未识别，并记录「来源内存在多个值」。
3. **不重算**：完成数、总数、百分比、最新阶段、最慢阶段只引用系统已算好的值，模型不得自行除法或重新判断。
4. **最新版优先**：技术协议、设备清单均默认取当前项目最新版本。
5. **来源可追溯**：正文按章节标注来源文件、版本与日期；每个抽取字段保留原文证据与页码，供人工核对；文档正文不展示内部 ID、表名、字段名。
6. **人工值优先**：人工替换 / 补录的值与 AI 结果分开存储；AI 重新生成不得覆盖人工值。

## 4. 逐段字段定义

### 4.1 基本信息

| ID | 字段 | 来源 | 规则 | 缺失 |
|---|---|---|---|---|
| F-01-01 | 项目编号 | 系统项目档案 projects.code | 原样 | —（必有） |
| F-01-02 | 项目名称 | 系统项目档案 projects.name | 原样 | —（必有） |
| F-01-03 | 项目周期 | 系统任务 / 阶段日期 | 计划区间 + 实际区间，见下 | 两者皆空 → 未识别 |
| F-01-04 | 甲方 | 技术协议「甲方名称 / 甲方 / 委托方 / 买方」 | 最新版；单位全称 | 未识别 |
| F-01-05 | 客户 | 技术协议「客户 / 最终用户 / 使用单位 / 业主」 | 最新版；**不与甲方自动同值** | 未识别 |
| F-01-06 | 地址 | 技术协议「项目地址 / 实施地点 / 建设地点 / 场地地址」 | 取项目地址，不取甲方注册地址 | 未识别 |
| F-01-07 | 项目组成员 | 项目经理 ∪ 任务负责人 | 见下；**不使用项目成员名册** | 未识别 |

**项目周期（F-01-03）**

- 计划区间 = 任务最早 `plannedStart` ~ 最晚 `plannedEnd`；
- 实际区间 = 阶段最早 `actualStart` ~ 最晚 `actualEnd`；
- 项目未全部完成时，实际结束显示「进行中」；
- 实际开始全部为空时，回退「项目启动 / Project Startup」任务的 `plannedStart`（既有口径）；
- 展示格式：`计划 2026-05-15 ~ 2026-11-08；实际 2026-05-20 ~ 进行中`；
- 只有一端有值时按实际可用部分展示，缺失端写「未识别」。

**项目组成员（F-01-07）**

- 项目经理：项目档案中的全部项目经理，保持顺序，排在最前，标注「项目经理」；
- 任务负责人：所有任务（含未分组任务）的负责人，按人去重；
- 展示格式：`张三（项目经理）、李四、王五`；
- 待分配任务（无负责人）不计入；
- 离职 / 停用人员仍按系统记录显示姓名；
- 合并后为空 → 未识别。

### 4.2 设备布局

| ID | 内容 | 来源 | 规则 | 缺失 |
|---|---|---|---|---|
| F-02-01 | CAD 布局图 | 最新版技术协议自动判页 | AI 判断「布局图 / 平面布置图 / CAD 图」页；支持人工替换 | 未识别 |
| F-02-02 | 三维图 | 最新版技术协议自动判页 | AI 判断「三维图 / 效果图 / 渲染图」页；支持人工替换 | 未识别 |

- 图片按页渲染，保留原始比例；
- 标注来源页码，如「技术协议第 12 页」；
- 人工替换后以人工值为准，AI 重生成不覆盖；
- 同一张图不得同时作为布局图与三维图。

### 4.3 项目基础信息及背景描述

| ID | 内容 | 来源 | 规则 |
|---|---|---|---|
| F-03-01 | 背景描述 | 技术协议「项目背景 / 需求 / 建设目标 / 项目概述 / 场地信息」+ 项目备注 | 200–400 字 AI 摘要；只整理原文，不推断 |

- 技术协议优先，项目备注作为补充；
- 两者都没有 → 未识别；
- 不写营销话术，不写「加强沟通」「持续关注」等空话；
- 协议与备注冲突时不自行取舍，列出「来源间存在差异」。

### 4.4 设备清单

| ID | 内容 | 来源 | 规则 |
|---|---|---|---|
| F-04-01 | 设备分类表 | 最新版设备清单 Excel | 按「分类名称」列聚合，不二次归并 |

表列：

| 分类名称 | 条目数 | 数量 | 代表物料 |
|---|---|---|---|
| 单层桌子 | 1 | 1 套 | 650×1300mm |
| L型单层桌子 | 1 | 2 套 | 1300×1950mm |
| 流利条格口滑槽 | 1 | 207 个 | 1730×630×100mm |

规则：

- 文件优先取类型 =「设备清单」的当前版本；无类型标记时按文件名含「设备清单 / 物料清单」识别；
- 表头需同时包含「分类名称 + 物料名称/项目内容 + 数量 + 单位」；
- 只取 `No` 为数字的数据行；跳过「合计 / 小计 / 备注 / 说明」行；
- 数量按单位分别汇总，不跨单位相加；
- 代表物料取该分类前 3 个物料名称 / 规格；
- 设备清单缺失、解析失败或找不到合法表头 → 未识别。

### 4.5 实施进度汇总

| ID | 内容 | 来源 | 规则 |
|---|---|---|---|
| F-05-01 | 进度文字 | 系统任务 / 阶段统计 | AI 只引用，不重算 |
| F-05-02 | 进度表格 | 系统阶段 / 任务 | 见下 |
| F-05-03 | 仪表盘 | 系统任务完成数 / 总数 | 完成率 = 系统给出的百分比 |

进度文字必须覆盖：

- 任务完成数 / 任务总数 / 完成百分比；
- 最新阶段（已动工任务中阶段序最靠后者）；
- 最慢阶段（阶段序中第一个仍有未完成任务的阶段）；
- 已完成阶段与未完成阶段的概况。

进度表格列：

| 阶段 | 状态 | 计划起止 | 实际起止 | 任务完成数 | 完成率 |
|---|---|---|---|---|---|

规则：

- 百分比直接取系统值；总数 0 时仪表盘显示「未识别」；
- 最新阶段不得写成「已进入」「正在验收」「验收通过」；
- 最慢阶段不得解释为项目失败或责任归属；
- 仪表盘只展示整体任务完成率，不引入未定义指标。

### 4.6 现场图片

| ID | 内容 | 来源 | 规则 |
|---|---|---|---|
| F-06-01 | 现场图片 8–12 张 | 日报现场工作附图 | 按日期分层抽样，去重 |

抽样规则：

1. 取有现场附图的已提交日报，按日期升序；
2. 每个有图日报轮流取 1 张，直到达到 12 张或取完；
3. 不足 8 张时有多少取多少；
4. 同一 `fileId` 只出现一次；
5. 每张标注「日期 + 日报作者」；
6. 无任何现场图 → 未识别。

**问题记录表（全量）**

| ID | 列 | 来源 |
|---|---|---|
| F-07-01 | 序号 | 生成 |
| F-07-02 | 问题描述 | issues.title |
| F-07-03 | 分类 | issues.categories |

| F-07-05 | 责任人 | issues.ownerName |

| F-07-08 | 关闭日期 | issues.closedAt |
| F-07-09 | 问题图片 | 问题附图 `file_links(object_type=issue)` |

规则：

- 包含未解决、处理中、已完成全部问题；
- 无解决方案 / 关闭日期显示「—」；
- 图片只嵌入展示，不做图片内容识别；
- 表内缩略图最多 3 张，超出显示 `+N 张`；
- 完整问题图片放「附录 A 问题图片附录」，按问题序号分组；
- 无图片显示「—」。

**AI 问题总结**

- 统计口径：全部问题（含已完成）；
- 按问题归类十项统计：机械部 / 采购部 / 规划部 / 项目部 / 物流原因 / 供应商原因 / 客户原因 / 客观原因 / 生产原因 / 其它原因；
- 聚焦数量最多的前两个分类，写明分类名、问题数、主要原因与处理情况；
- 重点写未解决与处理中的问题；
- 已完成问题可按分类合并概述；
- 系统「已完成」不得写成客户已验证或验收通过；
- 问题总数、状态计数只引用系统值。

## 5. 技术协议定向抽取

对最新版技术协议做固定字段抽取，而不是通用摘要。每个字段输出：

```
{ value, evidence, sourcePage, confidence, status }
```

`status` = `found` / `not_found` / `conflict` / `failed`；除 `found` 外页面统一显示「未识别」。

| 目标字段 | 识别写法 | 备注 |
|---|---|---|
| 甲方 | 甲方名称 / 甲方 / 委托方 / 买方 / 发包方 | 单位全称 |
| 客户 | 客户 / 最终用户 / 使用单位 / 业主 | 不与甲方自动同值 |
| 项目地址 | 项目地址 / 实施地点 / 建设地点 / 场地地址 | 不取甲方注册地址 |
| 项目背景与需求 | 项目背景 / 需求 / 建设目标 / 项目概述 | 用于 4.3 |
| 场地信息 | 场地信息 / 场地条件 | 并入 4.3 |
| CAD 布局图 | 布局图 / 平面布置图 / CAD 图 | 页图 |
| 三维图 | 三维图 / 效果图 / 渲染图 | 页图 |

规则：

- 乙方（浙江立镖机器人有限公司）不抽取、不展示；
- 封面页一般包含甲方名称与乙方名称，优先从封面与合同信息页取；
- 同一字段多处出现且不一致 → `conflict` → 未识别；
- 抽取失败不阻断其他章节。

## 6. 设备清单 Excel 解析

必须做结构化解析，不能依赖现有「文件 AI 分析」逐页摘要，原因：

- 现有文件分析每页最多 8 条 keyFacts，且明确要求不输出表格、不逐行抄写长表格；
- 设备清单需要完整读取分类、物料、数量、单位，逐页摘要会丢失明细。

解析步骤：

1. 选文件：类型 = 设备清单，取当前版本；否则按文件名识别；
2. 定位表头行；
3. 读取数据行并跳过汇总行；
4. 按「分类名称」分组；
5. 每组统计条目数、按单位汇总数量、取前 3 个代表物料；
6. 输出 4.4 表格。

异常处理：

- 多 sheet：取包含合法表头且数据行最多的 sheet；
- 合并单元格：向下填充分类名称；
- 表头缺失：未识别，并在系统内记录失败原因；
- 同一分类多个单位：分行展示，不合并成一个数量。

## 7. 与现有实现的差异

| 能力 | 现状 | 本清单要求 |
|---|---|---|
| 项目基本信息 | 已有编号、名称、经理、地区；无甲方、客户、项目地址 | 技术协议定向抽取甲方 / 客户 / 项目地址 |
| 项目周期 | 只有项目启动时间与计划日期范围 | 计划区间 + 实际区间 |

| 设备布局 | 无来源页图 | 技术协议自动判页 + 人工替换 |
| 背景描述 | 有项目文件通用摘要 | 技术协议定向摘要 + 项目备注 |
| 设备清单 | 无结构化解析 | 新增 Excel 解析与分类聚合 |
| 实施进度 | 已有统计与阶段数据 | 文字 + 表格 + 仪表盘 |
| 现场图片 | 只有张数，无图片引用 | 取 8–12 张并按日期分层 |
| 问题 | 有全量问题与分类 | 全量记录表 + 图片 + 前两分类总结 |
| 个人总结 | 无 | 新增人工填写与持久化 |
| 来源标注 | 有来源标签 | 章节级 + 附录级来源 |
