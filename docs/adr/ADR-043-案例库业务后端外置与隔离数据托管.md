# ADR-043：案例库业务后端外置与隔离数据托管

- 日期：2026-11-17
- 修订：2026-11-18 项目摘要改为受控只读投影，不建设整库只读副本
- 状态：草案（Proposed，C 方案）；用户已确认方向，待非作者评审与 PR 合并；未实现、未部署
- 主责：案例小组（业务后端）；LibiaoLink 案例数据网关（数据面、独立数据库、对象存储、项目摘要投影）
- 评审：wmj、px
- 关联：[案例库隔离数据面技术设计 v1.0](../案例库隔离数据面技术设计v1.0.md)

## 问题

旧 Case Hub 方案假定由 LibiaoLink 建设 case-api / case-worker，并承担案例审核、发布、撤回、外部读取和业务审计。这与最新边界不一致：

- 案例业务操作由案例小组控制，后端也由案例小组负责。
- 案例生产业务数据仍要保存在 LibiaoLink 托管的数据库中，案例小组本地不保存生产副本。
- 案例小组字段清单要求项目、案例、素材和主体只能调用受控接口，不得直连 LibiaoLink 数据库。
- 当前市场项目管理系统的数据库和后端不能受到影响，必须保证现有系统稳定运行。

因此需要重新确定控制面、数据面和核心系统之间的隔离方式。

## 决策

1. **案例小组后端是唯一业务控制面**：负责草稿、提交、审核、发布、撤回、分享、客户讲解、外部读取、用户、权限、会话和业务审计。
2. **LibiaoLink 不建设案例业务后端**：不建设审核、发布、撤回、分享、客户讲解和外部 published-cases 业务接口，不替案例小组决定状态流转。
3. **LibiaoLink 建设独立案例数据网关**：案例数据网关及其项目摘要投影任务，是案例数据库唯一的应用侧客户端，也是案例小组访问案例数据的唯一入口。
4. **案例小组不持有数据库和对象存储凭据**：案例小组后端只通过 HTTPS / mTLS / OAuth2 调用网关；不接收 libiaolink_case 账号、密码、连接串或永久 S3 凭据。
5. **网关只做数据面**：负责服务认证、Scope、项目摘要投影、案例数据落库、版本校验、幂等、发布快照持久化、素材上传和短时下载；不判断审核、发布或撤回是否合法。
6. **核心业务系统不改**：不新增核心表、不新增核心迁移、不修改 core-api / core-worker、不共享连接池、不共享 worker、不共享 outbox、不共享文件桶；核心侧仅新增最小权限只读账号用于项目摘要投影。
7. **生产使用独立 PostgreSQL 实例/独立集群**：libiaolink_case 不与 libiaolink 同实例，案例资源与核心资源独立计费和监控。
8. **项目主数据只读投影**：LibiaoLink 数据面使用专用只读账号（优先已有只读节点），按白名单字段查询核心项目并写入 `project_read.project_summary`；不建整库副本、不做物理主从复制；案例侧字段不写回核心项目表。
9. **项目使用核心原始 ID**：`externalProjectId` / `case.cases.source_project_id` 直接使用 `libiaolink.projects.id` 原始 UUID，不重新生成；不建立跨库外键，不做跨库 JOIN。
10. **公开读取在网关和数据库双层隔离**：案例小组公开服务使用只读 Scope；网关公开读取路径只连接只读角色，只返回 active published release，不能读取草稿、审核记录和未发布素材。
11. **案例迁移独立**：案例小组定义 schema 和迁移文件，LibiaoLink 使用独立迁移账户执行；案例 DDL 只能作用于 libiaolink_case.case，不得追加到核心 database/migrations/。

## 对案例小组字段清单第 1.3 条的解释

清单要求「案例库不得直连 LibiaoLink 数据库写入，只能调用受控接口」。本决策的解释是：

- 案例小组业务后端是业务控制面，但不是数据库客户端；它调用 LibiaoLink 案例数据网关。
- 案例数据网关及其项目摘要投影任务是唯一受控接口和案例数据库客户端；页面、BFF、分享页、公开服务和最终客户不得直连数据库。
- 网关不因“托管数据”而取得业务决定权；案例小组仍然决定审核、发布和撤回。
- 若未来要求案例小组直接持有数据库凭据，必须另立 ADR 重新评审，不能作为本 ADR 的实现细节。

## 对项目字段清单的落地修订

- 项目补充属性写入 `libiaolink_case.case.project_profiles`，不写核心 `projects`；需要核心项目页展示时另立需求。
- 素材 ID、对象键和下载票据由网关生成；案例小组不保存永久对象地址。
- `operatorUserKey` 由案例小组透传，网关不解释其角色和权限；业务审计仍由案例小组保存。

## 后果

- 旧 Case Hub 的案例业务后端、审核发布、外部读取和增量同步开发停止；现有 L0 骨架只作历史，不再扩展。
- 案例小组拥有独立发布节奏，LibiaoLink 不承担案例业务故障。
- LibiaoLink 需要提供独立案例 PostgreSQL 实例/独立集群、案例数据网关、对象存储、角色、网络策略、备份和项目摘要投影任务（专用只读账号，不复制整库）。
- 案例小组需要维护案例 schema 定义、业务后端、业务审计、公开读取权限和对象存储使用规范。
- 核心系统无需为案例发布、故障或迁移停机。
- 若案例小组后端、案例数据网关或案例数据库故障，只影响案例库，不影响核心项目系统。
- 网关成为案例数据的单点入口；必须独立扩容、限流、监控和演练，不能复用核心连接池。
- 独立 PostgreSQL 实例并不等于独立服务器。若只有一台服务器，C 方案只能实现数据/进程逻辑隔离，CPU、磁盘、网络和主机故障域仍共享，必须签认残余风险并做资源限额。

## 验证

- 核心代码与核心迁移零案例改动。
- libiaolink 无案例表、无案例列、无案例触发器。
- 项目摘要只做白名单投影；核心库不存在整库副本或物理主从复制。
- 案例小组网络无法连接核心主库和 libiaolink_case；只能访问案例数据网关。
- 只有案例数据网关及其项目摘要投影任务持有 libiaolink_case 应用账号；案例小组无数据库凭据。
- 网关接口清单不存在审核、发布决策、撤回决策、分享或客户权限判断。
- 公开只读路径无法读取 case.cases、case.case_reviews 和未发布素材。
- 案例库峰值压测时核心 API p95、错误率和数据库连接数不超基线。
- 停止案例数据网关、案例数据库或对象存储，核心系统正常。
- 案例库独立恢复演练不影响核心库。
- 若只有一台服务器，单机资源与故障域共享风险已记录，资源限额、监控阈值和扩容触发条件已验收。
