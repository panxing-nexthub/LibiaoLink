# 案例库远端主存 P0 增量字段字典（2026-11-21）

- 契约基线：案例数据网关 OpenAPI 1.9.0
- 迁移：`0015_release_history_asset_order_logo_and_operation_tombstone.sql`
- 适用范围：独立 `libiaolink_case` 数据库、案例数据网关、项目目录与案例素材桶
- 兼容性：新增路径、响应字段和数据库列；原单条发布历史路径保留。严格校验旧响应结构的客户端需重新生成类型。

## 1. 口径不变项

1. `project_summary` 仍是核心项目的只读投影，不新增本地项目行。
2. 本地项目仍存 `project_read.local_projects`，通过 `project_read.project_directory` 与核心投影合并读取。
3. `POST /api/v1/projects` 仅创建；更新、归档、解档、软删除和恢复使用 `PATCH /api/v1/projects/{projectId}`。
4. `externalProjectId` 跨全部核心历史摘要与本地项目永久唯一；`projectCode` 在目录可用项之间跨来源唯一。
5. 核心项目摘要以常驻 `watch` 秒级刷新；本地项目写后立即可读。

## 2. 发布历史枚举

### 2.1 接口

`GET /api/v1/cases/{caseId}/releases`

- Scope：`case-data:releases:history:read`
- `limit`：整数 1–100，默认 50
- `cursor`：上一页返回的签名游标；仅可原样使用
- 排序：`stagedAt DESC, releaseId DESC`
- 返回全部四态：`staged`、`active`、`superseded`、`withdrawn`
- `nextCursor: null` 表示末页

### 2.3 游标

游标载荷使用数据库原始 `staged_at::text`，保留微秒。不得由客户端把时间重格式化为毫秒；同 `stagedAt` 时以 `releaseId` 作为稳定次级键。

## 3. 案例素材排序

### 3.1 存储

`"case".case_asset_links.sort_order`

- 类型：`integer`
- 范围：`0..100000`
- 必填：是
- 默认：10
- 新挂接未指定时：当前最大值 + 10，最高截断为 100000
- 相同 `sortOrder`：按 `assetId` 升序稳定排序

### 3.2 挂接请求

`PUT /api/v1/assets/{assetId}/cases/{caseId}`

```json
{
  "operationId": "<uuid-v7>",
  "operatorUserKey": "case-authoring-client",
  "sortOrder": 90
}
```

`sortOrder` 可省略。已挂接素材再次 PUT 时，只有显式提供不同值才更新顺序。`DELETE` 保持原请求结构，不接收排序参数。

### 3.3 素材摘要

`CaseAssetSummary` 新增：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `sortOrder` | integer 0–100000 | 是 | 案例范围列表返回当前案例的排序；项目范围列表为 null |
| `caseLinks` | `{caseId, sortOrder}[]` | 否 | 全部案例挂接，按顺序返回；最多 500 项 |

案例素材列表按 `sortOrder, assetId` 升序。切换项目范围时仍按素材更新时间倒序。

### 3.4 发布冻结

固化 release 时，网关只接收已挂接素材的精确版本，并按当前案例顺序重新编号为连续 `0..N-1`。固化后的发布历史与公开快照不随后续重排、解挂、归档或编辑变化。

## 4. 客户 Logo 版本冻结

### 4.1 引用对象

`CustomerLogoReference`：

| 字段 | 类型 | 可空 | 说明 |
|---|---|---:|---|
| `assetId` | UUID | 否 | 项目素材 ID |
| `assetVersionId` | UUID | 否 | 冻结的素材版本 ID |

无 Logo 时整个字段为 `null`。

### 4.2 出现位置

| 结构 | 字段 | 说明 |
|---|---|---|
| `CaseVersionSnapshot` | `customerLogo` | 每个不可变案例版本保存当时项目 Logo |
| `CaseReleaseReceipt` | `customerLogo` | staging、激活、撤回回执 |
| `CaseReleaseHistory` | `customerLogo` | 单条历史和列表项 |
| `PublishedCaseRelease` | `customerLogo` | 公开快照 |
| `projectSnapshot` | `customerLogo` | 发布时项目摘要内的冻结引用 |

数据库 `"case".case_releases` 另存：

- `customer_logo_asset_id`
- `customer_logo_asset_version_id`
- `customer_logo_object_version_id`

三项同时为空或同时非空，并通过复合外键引用 `case_assets(id, asset_version_id, object_version_id)`。

### 4.3 哈希与恢复

- `projectSnapshotHash` 的计算输入包含 `customerLogo`。
- Logo 从 A 切到 B 后，相同案例正文和项目字段也会得到不同的项目快照哈希。
- 恢复旧案例版本时，使用该旧版本快照中的 `customerLogo`，不回填当前项目 Logo。
- 已归档或已替换的 Logo 不改变历史版本和历史 release 的引用。

### 4.4 删除与公开读取

- 删除被任一 release 或 Logo 快照引用的素材返回 `409 ASSET_REFERENCED`。
- 仅归档 Logo 允许继续读取。
- 公开入口：

`GET /api/v1/public/cases/{caseId}/releases/{releaseId}/assets/{assetVersionId}/content`

该入口同时接受发布素材和发布客户 Logo 的精确 `assetVersionId`。响应仍由网关按对象版本签名取流，不暴露桶名或永久对象键。

## 5. operation 保留与过期

### 5.1 结果

- 首次提交结果至少保留 30 天。
- 同 `operationId`、同请求体：返回首次状态码和响应体，不重复执行。
- 同 `operationId`、不同请求体：`409 IDEMPOTENCY_CONFLICT`。
- 超过 30 天或 `purged_at` 非空：`410 OPERATION_EXPIRED`。
- 未提交、未知或属于其他 `client_id`：`404 NOT_FOUND`。

### 5.2 查询接口

`GET /api/v1/operations/{operationId}` 返回：

```json
{
  "operationId": "<uuid-v7>",
  "statusCode": 201,
  "response": { "externalProjectId": "<uuid>" },
  "resourceId": "<uuid>",
  "createdAt": "2026-11-21T05:45:33.000Z",
  "expiresAt": "2026-12-21T05:45:33.000Z"
}
```

过期或墓碑化不返回旧响应体，返回：

```json
{
  "code": "OPERATION_EXPIRED",
  "message": "操作结果已超过 30 天保留期，禁止使用同一标识再次执行",
  "details": [],
  "traceId": "<uuid>"
}
```

### 5.3 清理

清理把记录转为墓碑，不物理删除：

- `response = null`
- `purged_at = statement_timestamp()`
- 保留 `operation_id`、`client_id`、`request_hash`、`created_at`、`expires_at`
- 清理输出字段：`confirmed`、`tombstoned`

这样原 `operationId` 在恢复备份或跨月重试后仍不会产生第二次业务写入。

## 6. 迁移 0015 数据库增量

| 对象 | 变更 |
|---|---|
| `case.case_asset_links` | 新增 `sort_order integer not null default 10`、范围 CHECK、案例排序索引 |
| `case.case_releases` | 新增客户 Logo 三项冻结列、同时为空/非空 CHECK、精确版本复合外键 |
| `case.published_release_v` | 增加客户 Logo 三项列 |
| `case.published_release_logo_v` | 新增公开读视图，供 `case_gateway_public_ro` 查询 |
| `case.case_idempotency_keys` | `response` 可空，新增 `purged_at`，调整响应/墓碑互斥 CHECK |
| `case.purge_case_operation_results(text, uuid[])` | 改为写墓碑并返回墓碑化数量 |

迁移为 forward-only；回滚使用应用包和数据库备份恢复到 0015 前状态，不执行逆向 SQL。

## 7. 错误码

| HTTP | 代码 | 场景 |
|---:|---|---|
| 409 | `CUSTOMER_LOGO_NOT_FOUND` | 项目 profile 指向的 Logo 没有可用素材版本 |
| 409 | `ASSET_REFERENCED` | 删除被发布历史或客户 Logo 快照引用的素材 |
| 409 | `IDEMPOTENCY_CONFLICT` | 同 operationId 使用不同请求体 |
| 410 | `OPERATION_EXPIRED` | operation 超过保留期或已墓碑化 |
| 422 | `VALIDATION_FAILED` | `sortOrder` 越界、游标查询参数非法等 |
