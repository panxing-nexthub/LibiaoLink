## 0. 结论

1. **案例业务操作全部由案例小组控制**：草稿、提交、审核、发布、撤回、外部读取、用户、权限、分享、会话和业务审计都在案例小组后端。
2. **LibiaoLink 不建设案例业务后端**：不建设审核、发布、撤回、分享、客户讲解和外部 published-cases 业务接口，不替案例小组决定状态流转。
3. **LibiaoLink 建设独立案例数据网关**：案例数据网关及其项目摘要投影任务，是案例数据库唯一的应用侧客户端；网关负责认证、Scope、项目目录、案例数据落库、版本校验、幂等、素材上传与短时下载，项目投影任务只向案例库写入白名单摘要。案例小组后端不持有数据库或对象存储凭据。
4. **网关只管理数据请求，不管理业务审核**：案例小组后端决定草稿、提交、审核、发布和撤回；网关只接收已经决定的最终数据，并保证写入安全、可追溯和不覆盖。
5. **市场项目管理系统核心业务库与核心后端不改**：不增加案例表、不增加核心迁移、不修改 core-api / core-worker、不共享连接池、不共享消息队列；核心侧仅新增最小权限只读账号用于项目摘要投影。
6. **生产必须使用独立 PostgreSQL 实例**：案例库不得与 libiaolink 同实例。只有一台服务器时，应在同一主机运行独立 PostgreSQL 集群/端口/数据目录，并配置独立连接池、备份和资源限额；CPU、内存、磁盘、网络和主机故障域仍共享，必须签认残余风险，不能宣称物理隔离。
7. **本地项目与核心项目分源存储、统一目录**：案例小组可通过 `case-data:projects:write` 在 `libiaolink_case` 注册、更新和归档本地项目，不写核心库；本地项目单独存放，与核心只读投影按项目 UUID 合并查询。`project_summary` 的字段、单向投影职责和网关只读权限保持不变。

> 对外表述统一为：**案例小组拿业务后端；LibiaoLink 拿数据网关和数据库。案例小组不碰数据库，只调受控接口。**

## 1. 口径修正

### 1.1 对案例小组清单第 1.3 条的落地解释

清单第 1.3 条要求「案例库不得直连 LibiaoLink 数据库写入，只能调用受控接口」。本设计按以下方式落地：

- 案例小组**业务后端（含作者端与公开端）**是业务操作和状态机的唯一控制方。
- 案例小组后端通过 HTTPS / mTLS / OAuth2 客户端凭据调用 LibiaoLink **案例数据网关**；不接收 libiaolink_case 的数据库账号、密码或连接串。
- 网关 API 请求路径只连接 libiaolink_case 和 project_read，不连接 libiaolink，不调用核心业务写接口；项目摘要投影任务使用专用只读账号读取核心，且不与业务请求路径共用连接。
- 页面、BFF、分享页、客户讲解页和最终客户只能经案例小组业务后端访问；它们不能直连数据库，也不能绕过网关。
- 网关不是旧 Case Hub 的翻版：它不判定审核通过、不决定发布、不执行撤回，只保存案例小组后端已经决定并提交的数据与发布快照。
- 网关不可用时，案例业务返回明确的 503 / 待同步状态；不得降级为直连数据库或写核心库。

### 1.2 对旧 Case Hub 口径的替代

旧方案中的以下内容停止执行：

- LibiaoLink 内部实现案例审核、发布、撤回和案例状态机。
- LibiaoLink 对外提供案例发布、撤回、分享或客户讲解业务接口。
- LibiaoLink 建设完整 case-api / case-worker 业务后端。
- 由 LibiaoLink 的 Case Hub 服务保存案例权限、分享和业务审计。

现有 `server/src/modules/case-hub` 的 L0 骨架只作为历史技术验证，不再扩展为正式案例业务后端，也不得接入核心 `AppModule`。新的案例数据网关不是该骨架的续建，二者不得混用。

## 2. 目标与非目标

### 2.1 目标

- 案例小组拥有完整业务控制权，可独立发布和迭代其业务后端。
- 案例主体业务数据（案例内容、发布快照、素材元数据等）落在 LibiaoLink 托管的独立数据库中，不留在案例小组本地作为生产副本。
- 案例小组后端不接触数据库凭据和对象存储永久凭据，只通过受控数据接口读写。
- 核心市场项目管理系统的数据库、API、worker、通知、文件、权限和性能不受影响；单机部署的资源争用风险按 §10.1、§12 第 13 项单独签认。
- 案例库故障、发布、迁移、备份和恢复不影响核心系统。
- 项目主数据只读；项目 ID 使用核心原始 UUID；案例侧字段不写回核心项目表。
- 外部客户只能经案例小组公开服务读取已发布内容。

### 2.2 非目标

- 不在 LibiaoLink 内实现案例审核、发布、撤回、分享和客户讲解。
- 不提供任意 SQL、数据库代理或通用 DDL API。
- 不让案例小组直接连接核心 libiaolink 数据库。
- 不修改 projects、users、project_members、tasks、files 等核心表。
- 不把案例迁移混入 database/migrations/。
- 不把案例附件放入核心文件桶或复用核心文件表。
- 不要求核心系统为案例查询增加同步接口、后台任务、表、列、索引、视图、函数或触发器；仅允许新增最小权限只读账号。
- 不把项目补充属性写回核心 projects；需要核心项目页展示时必须另立需求。

## 3. 总体架构

```text
案例库页面 / 分享页 / 外部客户
          │
          ▼
案例小组业务后端（他们）
  ├── 作者端 API / 审核 / 发布 / 撤回
  ├── 外部发布读取 API
  ├── 用户 / 角色 / 权限 / 分享 / 会话
  └── 业务审计
          │
          ├── HTTPS / mTLS / OAuth2（只接受受控数据接口）
          ▼
LibiaoLink 案例数据网关（独立进程，不属于 core-api）
  ├── 服务认证 / Scope / 限流 / 请求日志
  ├── 项目目录只读查询（读 project_read 投影）
  ├── 案例数据 CRUD / 版本校验 / 幂等
  ├── 发布版本 staging / 激活 / 撤回 / 已发布版本只读
  └── 素材上传会话 / 短时下载票据
          │
          ├── SQL（案例数据库唯一应用侧客户端）──▶ libiaolink_case
          │                                      ├── case schema（案例业务数据）
          │                                      └── project_read schema（项目摘要投影缓存）
          └── S3 ──▶ 案例对象存储（独立桶 / 前缀）

案例小组本地库（他们）
  └── 用户、角色、权限、分享、会话、业务审计

市场项目管理系统（核心，保持不变）
  core-api / core-worker / libiaolink
          │
          └── 专用只读账号 ──▶ 项目摘要投影任务（LibiaoLink 数据面）──▶ project_read
```

核心系统与案例系统的唯一数据依赖是「项目摘要投影」。案例小组后端不访问核心数据库，也不调用核心写接口；网关 API 请求路径不访问核心数据库，项目投影任务只读核心并只向案例库写入白名单摘要。

| 案例外部读取、分享、客户讲解 | 案例小组 | 对外 API 和字段脱敏由他们实现 |

| 案例数据网关 | LibiaoLink | 只做数据面：认证、Scope、版本、幂等、落库、素材通道 |
| 案例表结构定义、业务字段变更 | 案例小组 | 提出 schema / 迁移，不直接执行数据库 DDL |
| libiaolink_case 实例、迁移执行、备份、监控 | LibiaoLink | 使用独立迁移账户执行，不参与案例业务逻辑 |

约束：

- libiaolink 中不新增任何案例表、列、触发器或案例索引。
- libiaolink_case 不保存核心用户账号、权限、邮箱或联系方式；`project_summary.manager_names` 只保存经批准的项目经理显示名缓存。
- 项目名称、编号、经理等核心主数据不复制成可写副本；发布快照是历史冻结值，不是主数据。本地项目是独立来源，不是核心项目副本。
- 核心项目的 `externalProjectId` / `sourceProjectId` 直接使用 `libiaolink.projects.id` 原始 UUID；本地项目由网关生成 UUIDv7，或接受调用方显式提供的 UUID。两类 ID 与项目编号都进入跨来源占用校验。
- 项目编号在目录可用项（未软删除且未标记源缺失）之间跨来源唯一，归档项仍占编号；项目 ID 跨全部历史摘要唯一。不得用同一编号登记两个可用目录项。
- 核心与案例库不建立跨库外键；`case.cases.source_project_id` 仅作稳定弱引用；核心项目删除、归档或软删除不级联删除案例数据。
- 案例小组本地库不保存项目、案例、素材的生产副本；只保存其自身用户、权限、分享、会话、业务审计、审核记录和 outbox 元数据。
- 项目补充属性只存 `case.project_profiles`，不写核心 `projects`；如果业务要求核心项目页显示这些值，必须另立需求并单独评审，不属于本方案。
- 审核动作、审核结论、审核意见和审批时间线以案例小组本地库为唯一事实源，不进入 `libiaolink_case`；案例库只在 `case_releases.approval_ref` 保存不透明引用。网关不得据此判断审核是否通过。

## 6. 字段落地

### 6.1 核心只读字段

从项目摘要投影读取，案例侧不改：

- projectId：核心 `projects.id`，作为 `externalProjectId`。
- projectCode：核心项目编号。
- projectName：核心项目名称。
- customerText：核心 `projects.customer` 文本，仅供展示，不作为客户稳定主体。
- region：核心项目地区。
- projectType：核心项目类型。
- managerIds：核心 `projects.manager_ids`。
- managerNames：经确认允许显示，通过核心 `users(id, display_name, updated_at)` 三个字段投影；只读显示名，不读取邮箱、组织、状态明细或联系方式。
- status、version、updatedAt、archivedAt、deletedAt。
- sourceVersion：核心项目取 `projects.version`；本地项目从 1 起，登记后作为本地目录项版本。

本地注册项目返回与核心项目相同的目录字段。本地项目的项目经理 ID / 显示名来自登记请求，不读取核心用户档案；经理集合可以为空。`project_summary` 不保存本地项目。

### 6.2 案例侧项目字段

案例小组清单中的以下字段属于案例业务数据，通过网关保存在 libiaolink_case.case，**不写回核心项目表**：

- 客户稳定键、客户显示名、客户别名、客户关系。
- 合作伙伴类型、其他合作伙伴、合作伙伴别名。
- 3PL 稳定键、显示名、别名。
- 项目成员 userKey、角色、主负责人、退出时间。
- 地区多值、国家、行业、业务场景、方案类型、可否参观等核心项目表没有的补充属性。

因此，核心 `projects.customer` 只作为旧项目文本展示；案例库的客户主体必须使用案例侧稳定键。核心项目表不新增客户主体、合作伙伴、3PL、案例角色或案例补充属性字段。

### 6.3 案例内容与发布状态

- title、summary、locale、changeSummary。
- 正文六分组、亮点、成效、方案参数。
- 每个正文内容字段的密级、客户分享、客户讲解、AI 使用和排序。
- 草稿、提交、审核通过、驳回等业务状态完全保留在案例小组本地库，不写入案例库；网关不保存、不解释、不判断业务状态流转。
- 发布可见性由 `case_releases` 的技术状态控制：`staged / active / superseded / withdrawn`。网关只在收到 `stageRelease`、`activateRelease`、`deactivateRelease` 数据请求时，执行案例小组后端已经作出的决定；网关不自行判断何时发布或撤回。
- 网关只校验字段类型、长度、版本、技术状态和幂等；任何业务合法性、审核结论、分享范围和客户权限均由案例小组后端判断。

### 6.4 素材字段

- fileId、assetId、assetVersionId、objectKey、文件名、MIME、字节数、SHA-256。
- 图片宽高、视频时长、扫描状态、预览状态、转码状态。
- 展示顺序、封面、客户 Logo、素材分类、密级。
- 文件本体写案例对象存储；数据库只存元数据和对象键。
- 素材 ID 和对象键由网关生成；案例小组不得自行拼接永久对象地址。

### 6.5 不进入案例库的数据

- 案例小组用户档案、角色、权限、分享授权、会话。
- 客户讲解访问记录。
- 登录、会话、分享授权和客户访问日志。
- 字段级变更历史、业务审计原文、审核动作、审核意见、审核结论、审批时间线和字段级审核状态。
- 核心任务、日报、问题、合同、成本、内部文件、核心权限。

这些数据按案例小组清单保留在其本地库或其业务审计系统中。

### 6.6 对字段清单落地口径的修订

- 清单 1.3 条按本设计执行：案例小组不直连数据库，只调用案例数据网关；不得把案例后端直连当作例外。
- 清单 3.3 的「项目补充属性写回 LibiaoLink」在当前零影响约束下解释为写入 `case.project_profiles`，不是写入核心 `projects`。
- `externalProjectId` 使用核心项目原始 UUID；`sourceVersion` 取项目摘要版本；`expectedVersion` 取案例记录版本。
- `operationId`、`traceId`、`operatorUserKey` 逐次写入透传；`operationId` 同时作为 `Idempotency-Key`，网关记录请求元数据，业务审计仍由案例小组保存。

## 7. 数据模型基线

### 7.1 project_read 项目目录（LibiaoLink 维护）

```text
libiaolink_case
  project_read.project_summary
    project_id
    project_code
    project_name
    customer_text
    region
    project_type
    manager_ids
    manager_names              -- 按已批准的 users.display_name 投影，顺序与 manager_ids 对齐
    status
    source_version
    source_updated_at
    archived_at
    deleted_at
    synced_at
    last_seen_at
    source_missing_at          -- 核心已查不到该项目时的对账标记，不删除摘要

  project_read.local_projects  -- 本地项目，独立于核心投影
    project_id / project_code / project_name / customer_text / region / project_type
    manager_ids / manager_names / status / source_version / source_updated_at
    archived_at / synced_at / created_at / updated_at

  project_read.project_directory -- project_summary union all local_projects
  project_read.project_code_claim -- 跨来源 project_id / project_code 唯一占用
```

- 由 LibiaoLink 项目摘要投影任务通过专用只读账号写入；只做白名单字段的派生缓存，不复制整库。
- 案例数据网关对核心投影只读；本地注册与 PATCH 更新写入独立的 `project_read.local_projects`，不写 `project_summary`。
- `project_read.project_directory` 把核心投影与本地项目按项目 UUID 合并，供目录查询、项目资料、案例创建和发布 staging 共用；`project_summary` 字段和只读权限不变。
- `project_read.project_code_claim` 维护跨来源的项目编号和项目 ID 占用；核心投影与本地项目插入/改号均由触发器校验，重复返回冲突。
- 只保留白名单字段，不同步任务、日报、合同、成本、人员隐私和核心文件。
- `manager_ids` 直接取核心 `projects.manager_ids`，项目使用核心原始 UUID。
- `manager_names` 已确认启用：按 `manager_ids` 顺序投影核心 `users.display_name`，只授予 `users(id, display_name, updated_at)` 三个字段，不读取邮箱、组织、状态明细或联系方式。
- 姓名投影另设 `users.updated_at` 水位，只刷新当前摘要中引用的 `manager_ids`；姓名变化只更新展示缓存，不冒用项目 `source_version`，也不改写历史发布快照。
- 增量同步按 `source_updated_at` / `project_id` 水位推进，并保留重叠回看窗口，防止长事务晚提交导致漏数；不得只靠一次 `updated_at` 水位。
- 数据面默认常驻运行 `watch`，每 1000ms 执行一轮增量，单轮通常远小于 1 秒，项目目录变更目标为秒级可见；不得以 5 分钟定时刷新作为正常链路。`CASE_PROJECTION_OVERLAP_SECONDS` 默认 300 秒只表示长事务安全回看范围，不是刷新周期。
- 低频执行全量 ID 对账：只有一次无错误、完整结束的全量扫描才能参与缺失判断；连续两次完整扫描都缺失的项目写 `source_missing_at`，再次出现时清除该标记。对账不删除本地摘要、不级联删除案例。软删除和归档分别保留 `deleted_at`、`archived_at`。
- 项目选择器返回目录视图中所有 `deleted_at is null` 且 `source_missing_at is null` 的核心与本地项目，包含 `status = archived` 并明确标记；软删除、核心已彻底删除或无目录项的项目不可用于新建案例。
- 项目目录返回 §6.1 全部已批准字段，不另设项目白名单；归档项目可选，软删除和源缺失项目仅保留历史案例读取能力。

### 7.2 case（案例小组定义，网关落库）

至少包含：

- case.project_profiles：案例侧项目补充属性。
- case.subjects：客户、合作伙伴、3PL 主体。
- case.subject_aliases：主体别名。
- case.project_subjects：项目与主体关系。
- case.project_members：案例项目成员与角色。
- case.cases：案例内容、正文和版本。
- case.case_releases：不可变发布版本、项目快照、发布哈希、approvalRef。
- case.case_assets：素材元数据。
- case.case_release_assets：发布版本与素材关系。
- case.case_idempotency_keys：幂等键。
- case.case_schema_migrations：案例独立迁移记录。
- case.published_release_v：只暴露 active published release 的只读视图。

不给案例小组创建以下表：

- case.users、case.roles、case.permissions、case.shares、case.sessions：归他们本地库。
- 核心 users、projects、project_members、files 等表的副本。

案例库不创建 `case.case_reviews`。审核动作、意见、结论和时间线只保存在案例小组本地库；案例库只保存 `case_releases.approval_ref`。

### 7.3 发布版本与状态切换

- `case_releases` 按 `case_id + release_no` 唯一；状态固定为 `staged / active / superseded / withdrawn`。
- 同一案例最多一个 `active` release，用部分唯一索引兜底；并发切换必须在案例级事务锁内完成。
- 创建发布只进入 `staged`：网关接收案例 payload、`sourceVersion`、项目快照依据和素材版本清单，在同一事务中校验 `sourceVersion` 对应当前 `project_directory`，固化项目快照、`payload_hash`、`staged_at` 和素材版本关系。
- 项目快照只在 staging 时固化；`activate` 不重新读取核心主数据，不静默刷新已审核快照。项目在审核后发生变化时，是否重新审核并重新 staging 属于案例小组业务决定；他们调用新的 `stageRelease` 即可。
- 激活由案例小组后端显式调用 `activateRelease`。网关在事务内锁定案例行，校验目标 release 属于该案例、状态为 `staged`、全部素材版本已就绪、`expectedActiveReleaseId` 等于当前 active release（无 active 时必须显式传 `null`），然后把旧 active 置为 `superseded`，把目标 release 置为 `active`。
- 撤回由案例小组后端显式调用 `deactivateRelease`。网关校验目标 release 就是当前 active 且 `expectedActiveReleaseId` 匹配，然后置为 `withdrawn`，写 `withdrawn_at`；保留快照和素材，不删除历史。
- `approvalRef` 是案例小组审核决定的不透明引用，激活时保存到 `case_releases`；网关只校验必填、长度和字符集，不读取、不复核、不推断审核内容。审核动作、意见、结论和时间线不进入案例库。
- 发布快照和发布素材不可原地修改；状态字段、状态时间是唯一允许变更的部分。已发布版本只解析 `active` release；`withdrawn` 外部一律 404，内部作者 Scope 可读取历史。
- `case_release_assets` 必须绑定 `asset_version_id` / `object_version_id`，不能只绑定可变的当前对象键。
- 激活前必须校验每个素材版本的对象存在、哈希一致、扫描/转码状态符合网关技术门禁；任何一项未就绪返回 409，不得降级为当前对象键读取。
- 重复的 `activateRelease` / `deactivateRelease` 以 `operationId` 幂等收敛；新的操作键对非允许状态执行时返回 409。网关只判断技术状态，不判断业务上是否应当发布或撤回。

### 7.4 项目与新库关联规则

- 案例侧 `case.cases.source_project_id` 存目录项 `externalProjectId`：核心项目为核心 `projects.id` 原始 UUID，本地项目为案例库生成的 UUIDv7。
- 网关在首次创建案例时校验该 ID 存在于 `project_read.project_directory`，且 `deleted_at` / `source_missing_at` 为空；核心项目需已完成投影，本地项目需已登记。未完成投影同步或不在目录中的项目不可选，不得回退为直连核心校验。不建立跨库外键，不做跨库 JOIN。
- 项目改名、换经理、归档或软删除只更新摘要，不覆盖历史发布快照。
- 已发布案例读取使用发布时项目快照；未发布草稿使用当前摘要，并显示投影同步时间 `synced_at`。

## 8. 网关接口与操作归属

### 8.1 操作归属

以下操作全部由案例小组后端完成，LibiaoLink 不提供对应业务 API：

- 创建 / 修改草稿。
- 提交审核。
- 审核通过 / 驳回。
- 业务发布决定 / 撤回决定。
- 生成分享链接、客户讲解会话和授权。
- 确定字段可见范围和客户侧脱敏。

### 8.2 网关数据接口

网关按资源提供受控数据接口，路径和字段以双方冻结的 OpenAPI 为准。接口类别固定为：

- 项目目录只读：按分页读取 `project_read.project_directory`，合并核心投影与本地项目，供案例小组选择项目；核心项返回核心原始 UUID，本地项返回案例库 UUID。可见范围按已签认的业务规则过滤。
- 本地项目注册、更新与归档：按请求字段写入 `project_read.local_projects`，写入 `operationId` 幂等，项目编号在目录可用项间跨来源唯一、项目 ID 跨全部历史摘要唯一；PATCH 以 `expectedVersion` 防覆盖，`status=archived` 归档并可解档；返回目录项，不写核心库。
- 案例聚合读写：按 `caseId` 读取、保存草稿和案例版本；写入携带 `expectedVersion`。
- 发布版本 staging：`stageRelease` 保存案例小组已经冻结并送来的案例 payload、项目快照依据和素材版本，结果只能是 `staged`。网关不判断是否应先审核。
- 发布版本激活：`activateRelease` 执行案例小组已经决定的发布，把目标 `staged` 版本切换为唯一 `active`，保留旧版本并置为 `superseded`。
- 发布版本撤回：`deactivateRelease` 执行案例小组已经决定的撤回，把当前 `active` 版本置为 `withdrawn`。
- 操作结果查询：按 `operationId` 查询网关已执行的幂等结果，用于案例小组 outbox 重试和故障恢复。
- 已发布版本只读：供案例小组公开服务读取 `active` release 和发布时锁定的素材版本。
- 素材通道：创建上传会话、完成校验、签发短时下载票据。

网关明确**不提供**：提交审核、审核通过、拒绝、发布条件判断、撤回条件判断、分享授权、客户讲解会话和客户权限判断接口。`stageRelease`、`activateRelease`、`deactivateRelease` 是数据持久化动作，不是业务审批接口。

### 8.3 写入协议

每次业务写入至少携带：

- `operationId`：必填。案例小组后端为一次逻辑业务操作生成一次，重试不得更换；网关以同一值作为 `Idempotency-Key`。
- `externalProjectId`：目录项 UUID；核心项目使用核心原始 UUID，本地项目使用案例库生成的 UUIDv7。项目相关写入和发布 staging 必填。
- `sourceVersion`：仅在创建案例、项目目录校验和 `stageRelease` 时必填。`stageRelease` 必须与当前 `project_directory.source_version` 一致，不一致返回 409 `PROJECT_VERSION_CONFLICT`，不得自动刷新快照或自动升级版本。
- `expectedVersion`：更新案例、发布记录或本地项目时的当前记录版本；案例不一致返回 409 `VERSION_CONFLICT`，本地项目不一致返回 409 `PROJECT_VERSION_CONFLICT`。
- `expectedActiveReleaseId`：`activateRelease` / `deactivateRelease` 必填，值为 UUID 或显式 `null`；与当前 active release 不一致返回 409 `ACTIVE_RELEASE_MISMATCH`。
- `approvalRef`：`activateRelease` 必填，案例小组审核决定的不透明稳定引用；网关不解释其业务含义。
- `traceId`：双方日志串联；不参与幂等请求哈希。
- `operatorUserKey`：案例小组用户稳定键，网关只透传和记录，不解释其权限。

幂等与并发规则：

- 网关按“调用方 + `operationId`”保存规范化请求哈希、HTTP 状态、响应体、资源 ID 和过期时间；请求哈希不包含 `traceId`、认证头和其他传输头。
- 同 key、同请求哈希：直接返回首次结果，不重复写入、不重复切换状态。
- 同 key、不同请求哈希：返回 409 `IDEMPOTENCY_CONFLICT`，不得覆盖第一次结果。
- 同 key 并发请求：网关用唯一约束或行锁收敛；未完成的一侧返回 409 `IDEMPOTENCY_IN_PROGRESS` 并带 `Retry-After`，调用方必须用原 key 重试或查询结果。
- 幂等结果保留时间不得短于双方约定的最长重试窗口，默认不少于 30 天；清理任务只能删除已过期且无未完成 outbox 引用的记录。
- `stageRelease`、`activateRelease`、`deactivateRelease` 必须在数据库事务内完成；案例切换使用案例级锁和“同一案例仅一个 active”的部分唯一索引双重兜底。

网关校验认证、Scope、项目存在性、版本、技术状态、幂等键和字段格式。未认证返回 401，无 Scope 返回 403，不存在返回 404，版本/状态/幂等冲突返回 409，参数错误返回 422，超限返回 429。网关不判断案例业务角色，也不判断审核或发布是否合法。

### 8.4 公开读取隔离

- 公网和客户侧只经过案例小组公开服务。
- 案例小组公开服务调用网关的只读 Scope；网关只解析 `active` release 和其发布时锁定的素材版本，不能返回草稿、审核记录、内部备注和未发布素材。
- 公开读取路径使用独立的只读数据库角色 `case_gateway_public_ro`；作者写入路径使用 `case_gateway_authoring_rw`，两者不共用权限。
- 字段脱敏、可见范围、分享授权和客户权限仍由案例小组业务后端完成；网关和数据库视图只负责发布版本隔离。
- 公开缓存键必须包含 `caseId + releaseId`，回源只取对应发布快照和对象版本；`activate` / `deactivate` 后由案例小组使旧缓存失效。
- 撤回后旧分享链接立即失效并返回 404；公开 Scope 永远不返回 `withdrawn` release。案例小组内部通过作者 Scope 可以查看历史快照和素材，用于审计和重新发布准备。

### 8.5 跨系统操作一致性

不建立跨系统分布式事务。案例小组本地业务事务与网关落库通过 `operationId` + 本地 outbox 最终一致；网关不建设案例业务 outbox，也不替案例小组重试业务决定。

1. 案例小组后端在本地事务中写入业务决定、业务审计和 outbox 事件，三者同事务提交；业务决定未落本地库时不得调用网关。
2. outbox 事件一次性生成 `operationId`，之后所有重试、进程重启和人工补偿都复用它；不得因 HTTP 超时重新生成操作键。
3. 本地 outbox 状态建议固定为 `pending / succeeded / failed`。`pending` 可重试，`succeeded` 只保存网关返回的资源 ID 和结果，`failed` 只用于不可重试错误或人工终止。
4. 网关成功但本地未来得及标记时，重启后必须先用原 `operationId` 查询结果；若已有结果则直接收敛为 `succeeded`，不得再次发起新操作。
5. 请求超时属于结果未知，不得直接标记失败；先查询 `operationId`，查不到再以同一键重试。收到明确非重试错误后才可标记 `failed`。
6. 同一 `caseId` 的会改变发布状态的操作必须按本地 outbox 顺序串行投递；不并行执行 `stageRelease`、`activateRelease`、`deactivateRelease`。不同案例可并行。
7. 网关只提供数据幂等、版本冲突和操作结果查询，不根据审核、分享或客户状态决定是否执行；业务合法性由案例小组后端负责。
8. 网关不可用时，案例小组把操作保持为 `pending`，不得把尚未确认成功的数据对外展示为已发布；恢复后按原 `operationId` 补投。
9. 双方按 `operationId`、`traceId` 和资源 ID 对账；网关幂等结果至少保留 30 天，案例小组不得在该窗口内复用 `operationId`。
10. 不可重试失败后修改 payload 的，必须结束旧 outbox 事件并用新 `operationId` 新建操作；不得复用旧键提交不同内容。

## 9. 项目摘要投影隔离

- 不建设核心库整库只读副本，不做物理主从复制，不复制核心数据库。
- 核心侧唯一允许的运维变更是新增一个仅对项目目录白名单字段授予列级 `SELECT` 的专用账号；不新增核心表、列、索引、视图、函数、触发器或后台任务。若连该只读账号也不允许，必须改为核心主动推送项目目录，另立方案。
- 项目摘要投影任务优先使用已有只读节点；没有只读节点时，使用专用只读账号读取核心主库，并在只读事务中按白名单批量查询。网关业务请求路径不得连接核心数据库。
- 增量同步按 `(updated_at, id)` 水位前进，并回看一段安全窗口处理长事务晚提交；水位只能用于缩小扫描面，不能作为唯一正确性保障。
- 正常链路使用常驻 `watch`，默认 `CASE_PROJECTION_WATCH_MS=1000`，健康运行时的项目变更应在秒级进入目录；300 秒重叠窗口只用于兜住晚提交事务，不决定刷新频率。进程守护负责在配置或连接故障退出后重启；可恢复的 SQL 错误记录结构化日志后继续下一轮，不阻断后续刷新。
- 低频执行全量 ID 对账：只读取 `id, updated_at, deleted_at, archived_at` 等白名单列，更新 `last_seen_at`；只有一次无错误、完整结束的全量扫描才能参与缺失判断，连续两次都缺失的项目写 `source_missing_at`，再次出现时清除；不删除摘要、不级联案例。
- 项目选择器固定返回所有 `deleted_at is null` 且 `source_missing_at is null` 的目录项，包含核心项目与本地项目，包含归档并明确标记；不另设项目白名单。软删除、核心彻底删除和 `source_missing_at` 项目不得用于新建案例。
- 本地项目写入只进入 `libiaolink_case.project_read.local_projects`；项目 ID 通过 `project_code_claim` 在所有核心历史摘要与本地项目间永久去重，项目编号只在目录可用项（未软删除且未标记源缺失）之间跨来源去重；归档项目仍占编号。
- 项目目录接口返回 §6.1 的完整批准字段，包含项目经理 ID 和显示名；核心与本地项目按 UUID 合并分页。可按项目类型、状态、区域做检索筛选，但检索筛选不改变可见范围。
- 本地项目注册、更新和归档统一使用 `case-data:projects:write`；请求携带 UUIDv7 `operationId` 和 `operatorUserKey`，重试返回首次结果。`PATCH /api/v1/projects/{projectId}` 必须携带目录项当前 `sourceVersion` 作为 `expectedVersion`，版本不一致返回 409；`status=archived` 归档并设置 `archivedAt`，改回其它状态即解档。`externalProjectId` 不可变；项目编号变更继续执行跨来源唯一校验。
- 软删除、归档、核心项目彻底删除都不级联删除案例；历史案例读取发布时快照，不重新解释当前项目状态。
- 已创建但尚未发布的案例使用当前摘要，并展示 `synced_at`；投影延迟时不得回退为直连核心或写核心库。
- 项目经理显示名按已确认口径投影：只读核心 `users(id, display_name, updated_at)`，按 `manager_ids` 顺序填充 `manager_names`；不得读取其它用户字段。
- 投影任务限速、限并发、超时和失败重试；读取压力纳入核心性能基线，不得因案例流量扩容核心连接池。
- 项目摘要投影任务仅属于 LibiaoLink 数据面，不属于案例业务后端。

## 10. 隔离、安全与运维

### 10.1 数据库隔离

- 生产 `libiaolink_case` 必须使用独立 PostgreSQL 集群，不得与核心 `libiaolink` 共用同一个数据库实例、数据目录、服务进程和端口；只有一台服务器时也必须使用独立系统服务、独立数据目录、独立端口、独立 socket、独立连接池和独立备份。
- 案例库使用独立数据盘或独立配额，独立监控、独立备份、独立恢复演练；不与核心库共用 WAL 归档目录和备份任务。
- 案例库必须显式设置低水位资源上限：`max_connections`、`shared_buffers`、`work_mem`、`maintenance_work_mem`、`temp_file_limit` 均单独配置，并为核心库预留 CPU、内存、连接数和磁盘余量。具体数值按容量测试冻结，不允许沿用核心库参数。
- 每个案例连接设置 `statement_timeout`、`lock_timeout`、`idle_in_transaction_session_timeout`；网关连接池设置硬上限，禁止动态扩到核心池规模。
- 用 systemd/cgroup v2 为案例 PostgreSQL、网关和转码 worker 设置 `CPUQuota`、`MemoryMax`、`MemorySwapMax`、`TasksMax` 和 I/O 权重；案例进程被限额或 OOM 时不得拖垮核心进程。
- 磁盘水位采用分级限流：容量测试后冻结阈值，建议 75% 预警、85% 停止新建上传和转码、90% 停止案例写入但保留读取和撤回所需的必要控制面。阈值可调整，但不得取消告警和拒绝写入能力。
- 案例数据库不得监听公网；只允许案例数据网关、项目摘要投影任务和 LibiaoLink 运维网段访问。
- 案例小组后端所在网络不得开通 `libiaolink_case` 数据库端口，也不得持有数据库账号。
- 必须启用 TLS；数据库账号定期轮换，密码只放密钥管理，不落仓库。
- 案例迁移不得写入核心 `database/migrations/`，使用独立 `case_schema_migrations`。

### 10.2 对象存储隔离

- 生产使用独立案例桶，不复用核心文件桶；开发/测试若只能用前缀，必须使用独立凭据和独立生命周期策略，不能与核心对象混用访问密钥。
- 只有案例数据网关持有案例桶 S3 凭据；案例小组只使用上传会话和短时下载票据。核心文件凭据不得下发给案例小组。
- 开启桶版本控制。对象键按内容哈希或不可变资产版本生成，禁止覆盖写；数据库同时保存 `object_version_id`，发布关系只引用不可变版本。
- 公开读取必须用发布时锁定的对象版本签发短时 URL，签名参数包含版本 ID；不得按“当前对象键”重新解析。
- 生命周期策略、对象锁和垃圾回收只能删除未被任何 release 引用的对象。`staged`、`active`、`superseded`、`withdrawn` 引用的对象一律禁删。
- 删除素材前必须检查 `case_release_assets` 引用；被引用对象删除请求直接拒绝，不用软删除掩盖。
- 案例桶设置独立存储配额和磁盘水位告警；达到高水位时停止新上传和转码，不影响核心文件桶。
- 素材扫描、预览和转码使用独立进程与资源上限；失败任务不得无限重试，必须进入死信并告警。

### 10.3 部署隔离

- 案例数据网关独立部署、独立域名或独立入口，不进入核心 NestJS 进程。
- 网关不注册进 `AppModule`，不导入核心业务模块，不共享核心连接池、worker、outbox 或通知队列。
- 案例服务故障、重启、发布和回滚不影响核心；该结论以独立服务器或通过资源限额/容量门禁为前提。
- 核心 Nginx / API / worker 不需要为案例业务加载模块。
- 若必须共用入口，只增加独立 server/location、独立 upstream、独立连接池和独立限流区，不改核心应用路由和中间件。
- 案例 systemd 单元设置独立内存上限、任务数上限、重启退避和日志轮转；禁止无上限 fork、无限重启和写满根盘。
- 项目摘要 `watch` 作为独立长驻服务运行，配置自动重启、停止宽限期和日志采集；不得退化为每 5 分钟一次的定时任务。监控应能发现进程退出、连续错误和目录投影滞后。

### 10.4 请求治理

- Nginx 对案例入口设置 `limit_req`、`limit_conn`、`client_max_body_size` 和连接/读写超时；公开读、作者写、上传/转码、项目目录查询使用不同限流区，不能共享一个令牌桶。
- 网关按案例小组客户端限流、限并发、限请求体大小，并设置超时和熔断；超限返回 429 和 `Retry-After`，过载返回 503，不得排队到拖垮核心。
- 上传、转码和公开下载分别限流；大文件上传使用短时会话和分片限制，禁止一次请求占用无限连接。
- 网关请求日志记录 `traceId`、调用方、路由、状态码、耗时和资源 ID；不记录正文全文、素材内容和长期保留的下载票据。
- 案例数据网关的容量、连接池、线程/进程并发独立配置；核心数据库连接池不因案例流量扩容。
- 对慢查询、连接占用、磁盘水位、队列深度、5xx、429、OOM 和转码失败设置告警与扩容触发条件。

### 10.5 核心只读账号最小权限

- 只读账号建议命名为 `case_project_ro`，设置 `NOSUPERUSER NOCREATEDB NOCREATEROLE NOINHERIT`、小 `CONNECTION LIMIT`，仅从投影任务固定网段登录。
- 只授予 `projects` 必需列的 `SELECT`：`id, code, name, customer, region, project_type, manager_ids, status, version, updated_at, deleted_at, archived_at`。
- 禁止 `GRANT SELECT ON ALL TABLES`、禁止 schema 级全表授权、禁止写权限、禁止 DDL、禁止函数和触发器。
- 授予 `users(id, display_name, updated_at)` 列级 `SELECT`，仅用于项目经理显示名投影；不得读取邮箱、组织、状态明细或其他用户字段。
- 账号级设置 `default_transaction_read_only = on`、`statement_timeout`、`lock_timeout`、`idle_in_transaction_session_timeout` 和小 `CONNECTION LIMIT`。
- 密码由密钥管理下发并定期轮换；核心应用配置、核心迁移和核心代码不引用该账号。
- 验收时用该账号尝试 `INSERT`、`UPDATE`、`DELETE`、`CREATE` 和读取非白名单列，必须全部被拒绝。

## 11. 迁移、备份与回滚

- 案例小组定义业务 schema 和迁移文件；LibiaoLink 使用独立 `case_migrator` 账户执行，不向案例小组发放 DDL 凭据。
- 网关不提供任意 DDL / 任意 SQL 接口；schema 变更走迁移评审和发布流程。
- `project_read` 迁移由 LibiaoLink 维护，只作用于摘要投影表；不得在核心库创建对应表、视图或触发器。
- 核心迁移序列保持不变；任何案例 DDL 不得追加到 `database/migrations/`。
- 案例数据库独立全量备份 + WAL/PITR，案例对象桶开启版本控制并独立备份；备份任务、保留周期和存储不与核心共用。
- 恢复演练必须同时验证数据库记录与 `object_version_id` 对象可用。发布激活后发现任一对象版本缺失时，拒绝激活或回退到上一个 active，不得用当前对象键顶替。
- `active`、`superseded`、`withdrawn` 的发布快照、素材版本和对象版本不自动删除，禁止覆盖和生命周期清理；确需删除时只能按人工审批后的独立运维流程执行。
- 首期不对 `staged` 做自动清理；后续如启用清理，必须先制定 TTL、提前告警、引用检查和人工审批规则，不得直接由生命周期策略删除。
- 未完成上传、孤立对象和失败转码产物使用独立 TTL 垃圾回收；每次删除前查询 `case_release_assets`、发布版本和保留策略，存在引用即跳过。
- 幂等结果、操作日志和 outbox 对账信息独立于业务记录保留，至少覆盖最长重试窗口；恢复后允许案例小组用原 `operationId` 重放。
- 案例应用回滚不得要求回滚核心应用或核心数据库；案例库恢复也不得暂停核心服务。
- 恢复顺序固定为：对象版本可用性核验 → 案例数据库恢复 → 迁移版本核验 → 网关只读检查 → 激活/写入恢复。任何一步失败都保持案例入口 fail-closed。

## 12. 不影响核心系统的验收

上线前必须全部通过：

1. **代码零变更**：core-api、core-worker、AppModule、核心模块和核心迁移无案例改动。
2. **核心数据库结构零变更**：libiaolink 无新表、无新列、无触发器、无案例索引；仅新增最小权限只读账号用于项目摘要投影。
3. **网络隔离**：案例小组网络无法连接核心主库和 libiaolink_case；只能访问案例数据网关。
4. **网关唯一客户端**：只有案例数据网关及其项目摘要投影任务持有 libiaolink_case 应用账号；案例小组无数据库凭据。
5. **网关无业务决策**：接口清单和代码检查确认不存在审核、发布条件判断、撤回条件判断、分享或客户权限判断；只存在显式数据状态切换。
6. **公开读隔离**：公开 Scope 和 `case_gateway_public_ro` 只解析 `active` release；草稿、未激活、内部备注和未发布素材均不可读。`withdrawn` release 的旧外链返回 404，公开 Scope 不返回该 release；内部作者 Scope 可读取历史。
7. **故障隔离**：停止案例数据网关、案例数据库或对象存储，核心登录、项目、任务、文件、通知和 worker 正常。
8. **负载隔离**：案例接口按预期峰值压测时，核心 API p95、错误率和数据库连接数不超出基线阈值。
9. **备份隔离**：案例库恢复演练不影响核心库，也不需要停止核心服务。
10. **迁移隔离**：空库核心迁移、schema 检查、boundaries 检查结果不变；案例迁移只在独立实例执行。
11. **项目摘要投影只读**：项目摘要通过专用只读账号按白名单投影，不产生核心写入；不建立核心业务函数、触发器或整库副本。
12. **对象存储隔离**：案例桶凭据只下发给网关；案例小组只拿上传会话和短时下载票据。
13. **单机风险已签认**：若生产只有一台服务器，必须记录资源/故障域共享的残余风险、责任人和监控阈值；没有签认不得上线，也不得对外表述为核心绝对零影响。
14. **发布状态机**：`staged` 对外不可见；首次激活只产生一个 active；切换激活把旧 active 置为 superseded；撤回把当前 active 置为 withdrawn；并发激活同一案例只能有一个成功，其余返回 409。
15. **发布幂等**：重复 `activateRelease` / `deactivateRelease` 使用同一 `operationId` 不产生第二次状态变化；同 key 不同请求哈希返回 409；超时重试和进程重启后不重复发布。
16. **跨系统一致性**：模拟案例小组本地提交后、网关成功响应前进程崩溃；重启用原 `operationId` 查询或重试后只产生一个结果，本地 outbox 收敛为 `succeeded`。
17. **发布素材版本锁定**：激活后替换或重新上传同名素材，已发布页面仍读取旧 `object_version_id`；缺失任一素材版本时激活失败。
18. **引用对象保护与保留**：删除或生命周期清理 staged / active / superseded / withdrawn release 引用的对象必须被拒绝或跳过；已发布历史版本和 staged 版本不自动删除，未引用上传垃圾可正常清理。
19. **单机资源限额**：案例 PostgreSQL 的 `max_connections`、内存、临时文件、磁盘配额和网关/转码 cgroup 限额生效；案例压测或磁盘高水位时核心进程不受影响，案例入口按阈值返回 429/503。
20. **核心只读账号最小权限**：`case_project_ro` 只能读取项目白名单列和 `users(id, display_name, updated_at)`；读取其它用户字段、写入、DDL、函数和触发器均被拒绝；`CONNECTION LIMIT`、`statement_timeout` 和只读事务生效。
21. **项目摘要对账**：长事务晚提交、项目改名、归档、软删除和核心彻底删除都能在增量 + 全量 ID 对账范围内收敛；核心缺失项目只打 `source_missing_at`，不级联删除案例。
22. **业务口径落地**：项目目录返回全部未软删除项目并包含归档；软删除和 `source_missing_at` 项目不可新建案例；审核记录不进入案例库；撤回外链返回 404；经理姓名按批准字段显示。验收需逐项核对。
23. **本地项目分源存储**：通过 `case-data:projects:write` 注册本地项目后，合并目录可查询且可用于创建案例；PATCH 能更新字段并以 `expectedVersion` 防覆盖，`status=archived` 可归档并可解档。核心 `libiaolink.projects` 与 `project_summary` 不新增本地项目行。
24. **跨来源唯一**：同一项目编号不能同时存在于目录可用项中的核心投影和本地项目，也不能登记两个本地项目；软删除或 `source_missing_at` 历史摘要不占编号，归档项仍占编号。项目 ID 在所有核心历史摘要与本地项目间永久唯一。冲突返回 409 `PROJECT_CODE_EXISTS` / `PROJECT_ID_EXISTS`；源缺失核心项目带同号重新出现时阻断投影并保留冲突。

## 14. 口径状态

### 14.1 已确认业务口径（2026-11-18）

1. **项目目录**：返回核心投影与本地注册项目中全部 `deleted_at is null` 且 `source_missing_at is null` 的项目，包含归档并明确标记；不另设项目白名单。返回 §6.1 全部已批准字段。软删除、核心彻底删除和源缺失项目不可新建案例；已有案例和发布快照仍可内部读取。
2. **审核事实源**：审核动作、结论、意见、审批时间线和字段级审核状态只保存在案例小组本地库；`libiaolink_case` 不建 `case_reviews`，只保存 `case_releases.approval_ref` 和发布技术状态。
3. **撤回外链**：撤回后旧分享链接立即失效并返回 404；公开 Scope 永不返回 `withdrawn` release；案例小组内部作者 Scope 可读取历史快照和素材。
4. **项目经理姓名**：允许显示。只读核心 `users(id, display_name, updated_at)`，按 `manager_ids` 顺序投影 `manager_names`；不读取其它用户字段。
5. **保留策略**：`active / superseded / withdrawn` 发布快照、素材版本和对象版本不自动删除；`staged` 首期不做自动清理。后续启用清理必须另行制定 TTL、告警、引用检查和人工审批，不得直接交给对象存储生命周期删除。
6. **本地项目**：案例小组本地新建项目可在 `libiaolink_case` 注册并进入项目目录，不进入核心库；本地项目可通过 PATCH 更新或归档，写入使用 `expectedVersion` 乐观锁。项目 ID 跨来源永久唯一，项目编号在目录可用项范围内跨来源唯一，`project_summary` 保持只读投影不变。

### 14.2 技术联调前冻结

- 案例数据网关最终 OpenAPI 路径、错误码和字段命名。
- 单机容量基线、PostgreSQL 参数硬上限、cgroup 配额、磁盘水位阈值和扩容触发条件。
- 案例库与对象存储的 RPO / RTO、备份保留和恢复演练频率。
- 案例素材扫描、转码和预览由网关 worker 还是独立媒体服务承担。
- 是否具备第二台服务器；若长期只有一台，单机资源争用的风险接受人和扩容责任人。

## 15. 远端主存 P0 补齐（2026-11-20 落地）

### 15.1 项目目录与本地项目

- `POST /api/v1/projects` 仅创建本地项目；更新、归档、解档、软删除和恢复统一使用 `PATCH /api/v1/projects/{projectId}`。
- `GET /api/v1/projects/{projectId}` 返回与分页列表完全一致的目录项，核心与本地项目均按 ID 可读。
- 目录项没有独立 `rowVersion`；PATCH 的 `expectedVersion` 对应目录项 `sourceVersion`。本地项目创建为 1，每次真实修改加 1；核心项目继续映射核心 `projects.version`。
- 项目 profile 使用独立 `rowVersion`：首次保存 `expectedVersion=0` 返回 201，后续保存使用读取到的 profile `rowVersion`，另需与当前目录项一致的 `sourceVersion`。
- `externalProjectId` 在所有核心历史摘要与本地项目之间永久唯一；`projectCode` 在目录可用项之间跨来源唯一。归档仍占编号，软删除释放编号，恢复时若编号被占用返回 409。
- 本地项目只写 `project_read.local_projects`；`project_summary` 保持核心只读投影，不保存本地行。`project_directory` 是唯一合并读取口径。

### 15.2 案例版本与语言分组

- 调用方可在创建时预生成 `caseId`；同一语言一个案例，独立编辑、审核和发布。
- `translationGroupId` 将多个语言的案例组织为翻译组；省略时使用案例 ID。
- 首次创建保存版本 1；每次真实修改保存 `case_versions` 并递增 `rowVersion`。无实际变化的 PATCH 不新增版本、不递增版本号。
- `GET /api/v1/cases/{caseId}/versions`、版本详情和恢复接口可从远端恢复历史正文，不依赖案例小组本地正文副本。
- `GET /api/v1/projects/{projectId}/cases` 支持分页、状态、关键词和 `updatedAfter`；创建后立即读取和列表可见。

### 15.3 素材、版本和媒体

- 素材主身份为项目级 `assetId`；案例上传和项目上传都落在项目素材库，可挂接同项目多个案例。
- 新对象键固定为 `projects/{projectId}/assets/{assetId}/{assetVersionId}`；历史 `cases/*` 只保留读取。
- 同一 `assetId` 重新上传生成新 `assetVersionId`，历史版本不可变；record release 固定精确 `assetVersionId` 与 `objectVersionId`。
- 素材元数据包括 `assetType/title/description/locale/tags/classification/customerVisible/customerPresentationAllowed/shareAllowed`，更新使用独立 `rowVersion`。
- 支持 PNG、JPEG、WebP、AVIF、MP4 和 PDF；作者可获取短时预览或下载票据，票据不暴露桶名、对象键或永久凭据。
- 扫描、转码、预览和尺寸/时长由独立媒体服务负责，使用 `case-data:assets:process` 通过 `media-input`、`media-state` 接口回传。网关只校验版本、对象精确版本、SHA-256 和合法状态转移。
- 被 release 引用的素材删除返回 409 `ASSET_REFERENCED`；归档、编辑、删除或解挂不改写历史 release。

### 15.4 一致性、故障和配额

- 案例、项目 profile、素材、版本和幂等回执在同一案例库事务提交；2xx 后按资源 ID 立即读回。
- 核心项目投影默认 `CASE_PROJECTION_WATCH_MS=1000` 常驻 watch；300 秒重叠只处理晚提交事务，不是 5 分钟刷新周期。
- 所有写请求使用 UUIDv7 `operationId` 幂等至少 30 天；同键不同载荷返回 409 `IDEMPOTENCY_CONFLICT`。
- 版本冲突返回 409；429/503 按 `Retry-After` 重试；超时先查原 `operationId`，不得生成新键覆盖。
- 单服务默认 120 请求/分钟，总并发 16、单身份并发 6；单次 PUT 32 MiB，分片 8 MiB，总素材 256 MiB。
- 远端是唯一主存。网关不可用时保持本地 outbox `pending`，不得展示为成功；没有本地业务兜底。

### 15.5 存量迁移口径

没有批量单接口。存量迁移必须使用现有单资源接口、稳定 ID 和稳定 `operationId` 分批执行：项目 → 案例与语言版本 → 素材与版本 → 案例挂接 → release。项目保留原项目 ID 和编号，案例保留预生成 `caseId`；每批以按 ID 读取、项目案例分页、素材版本和操作回执对账。不得虚构“批量接口”，也不得在本地删除主存后才发现远端缺失。

### 15.6 Scope 与测试环境

| Scope | 使用方 |
|---|---|
| `case-data:projects:read/write` | 项目目录与本地项目 |
| `case-data:project-data:read/write` | 项目 profile、主体和成员 |
