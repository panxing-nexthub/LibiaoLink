## 三、新增接口与字段

### 3.1 发布历史列表

`GET /api/v1/cases/{caseId}/releases?limit=50&cursor=<cursor>`

- 排序：`stagedAt DESC, releaseId DESC`
- 状态：`staged`、`active`、`superseded`、`withdrawn`
- `nextCursor=null` 表示末页
- 游标签名绑定空筛选集，使用数据库原始微秒时间文本，避免毫秒截断漏项
- 原 `GET /api/v1/cases/{caseId}/releases/{releaseId}` 保持可用

### 3.2 素材排序

- `case_asset_links.sort_order`：整数，`0..100000`，默认 10
- `PUT /api/v1/assets/{assetId}/cases/{caseId}` 新增可选 `sortOrder`
- 素材摘要新增必返字段 `sortOrder`、`caseLinks`
- 未指定顺序的新挂接追加到末尾，步长 10；重复值按 `assetId` 稳定排序
- stage 时按案例当前顺序冻结为连续 `0..N-1`；后续重排不改变历史 release

### 3.3 客户 Logo

`customerLogo`：

```json
{
  "assetId": "<uuid>",
  "assetVersionId": "<uuid>"
}
```

无 Logo 时为 `null`。该字段出现在：

- 不可变 `CaseVersionSnapshot`
- `CaseReleaseReceipt`
- `CaseReleaseHistory`
- `PublishedCaseRelease`
- release 的 `projectSnapshot`

数据库以 `customer_logo_asset_id`、`customer_logo_asset_version_id`、`customer_logo_object_version_id` 锁定精确对象版本。`projectSnapshotHash` 包含 Logo；恢复旧案例版本保留旧 Logo；删除被发布历史引用的 Logo 返回 409 `ASSET_REFERENCED`；归档 Logo 仍可由公开发布素材入口读取。

### 3.4 operation 过期

- 结果至少保留 30 天
- 同 `operationId` + 同请求体：返回首次状态码和响应体
- 同 `operationId` + 不同请求体：409 `IDEMPOTENCY_CONFLICT`
- 过期或 `purged_at` 非空：410 `OPERATION_EXPIRED`
- 清理转为墓碑，保留键和请求哈希，防止恢复备份或跨月重试产生第二次写入
- 清理输出：`confirmed`、`tombstoned`

验收对象：

- 本地项目：`01a1fca3-72ed-75f6-b4e0-78e3b0a29d07`

通过项：

1. 本地项目创建 201、原地重放 201、不同载荷 409 `IDEMPOTENCY_CONFLICT`
2. 项目编号重复 409 `PROJECT_CODE_EXISTS`、跨来源项目 ID 重复 409 `PROJECT_ID_EXISTS`
3. `PATCH` 更新、归档、解档，`sourceVersion` 增至 4
4. 合并目录中本地项目可见，核心项目 PATCH 仍为 409 `PROJECT_SOURCE_READ_ONLY`

6. 案例版本 1 冻结 Logo A；切换 Logo B 后的新案例版本冻结 Logo B
7. 素材挂接顺序 B=10、A=20；列表按 B、A 返回
8. release 1 冻结 Logo A 和素材 B=0、A=1；重排为 A=5、B=15 后历史仍为 B=0、A=1
9. 6 个 release 完成激活/撤回；列表 `limit=2` 共 3 页，无重复，覆盖四态
10. Logo A/B 对应的 `projectSnapshotHash` 不同
11. 归档 Logo A 后，其发布内容仍返回 200，PNG 字节一致
12. operation 到期后 `GET /operations/{operationId}` 与 POST 重放均 410
13. 过期重放后项目仍为 `sourceVersion=4`；新 operation 同编号创建返回 409，证明未二次写入
