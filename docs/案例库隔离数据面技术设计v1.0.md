# 案例库隔离数据面技术设计 v1.0

> 日期：2026-11-17
>
> 修订：2026-11-18 项目摘要改为专用只读账号白名单投影，不建设整库只读副本。
>
> 状态：生效设计（C 方案：独立案例库 + 案例数据网关）。本文覆盖旧 Case Hub「由 LibiaoLink 建设案例业务后端」口径。
>
> 输入：案例小组《项目字段清单与标识规则 v1.2》（2026-11-17）；ADR-043。
>
> 主责：案例小组负责业务控制面和业务后端；LibiaoLink 负责独立案例数据网关、隔离数据库、对象存储和项目摘要投影；市场项目管理系统核心业务表与核心后端保持不变；核心侧仅新增最小权限只读账号用于项目摘要投影。

## 0. 结论

1. **案例业务操作全部由案例小组控制**：草稿、提交、审核、发布、撤回、外部读取、用户、权限、分享、会话和业务审计都在案例小组后端。
2. **LibiaoLink 不建设案例业务后端**：不建设审核、发布、撤回、分享、客户讲解和外部 published-cases 业务接口，不替案例小组决定状态流转。
3. **LibiaoLink 建设独立案例数据网关**：案例数据网关及其项目摘要投影任务，是案例数据库唯一的应用侧客户端；网关负责认证、Scope、项目目录、案例数据落库、版本校验、幂等、素材上传与短时下载，项目投影任务只向案例库写入白名单摘要。案例小组后端不持有数据库或对象存储凭据。
4. **网关只管理数据请求，不管理业务审核**：案例小组后端决定草稿、提交、审核、发布和撤回；网关只接收已经决定的最终数据，并保证写入安全、可追溯和不覆盖。
5. **市场项目管理系统核心业务库与核心后端不改**：不增加案例表、不增加核心迁移、不修改 core-api / core-worker、不共享连接池、不共享消息队列；核心侧仅新增最小权限只读账号用于项目摘要投影。
6. **生产必须使用独立 PostgreSQL 实例**：案例库不得与 libiaolink 同实例。只有一台服务器时，应在同一主机运行独立 PostgreSQL 集群/端口/数据目录，并配置独立连接池、备份和资源限额；CPU、内存、磁盘、网络和主机故障域仍共享，必须签认残余风险，不能宣称物理隔离。

> 对外表述统一为：**案例小组拿业务后端；LibiaoLink 拿数据网关和数据库。案例小组不碰数据库，只调受控接口。**

## 1. 口径修正

### 1.1 对案例小组清单第 1.3 条的落地解释

清单第 1.3 条要求「案例库不得直连 LibiaoLink 数据库写入，只能调用受控接口」。本设计按以下方式落地：

- 案例小组**业务后端（含作者端与公开端）**是业务操作和状态机的唯一控制方。
- 案例小组后端通过 HTTPS / mTLS / OAuth2 客户端凭据调用 LibiaoLink **案例数据网关**；不接收 libiaolink_case 的数据库账号、密码或连接串。
- 网关 API 请求路径只连接 libiaolink_case 和 project_read，不连接 libiaolink，不调用核心业务写接口；项目摘要投影任务使用专用只读账号读取核心，且不与业务请求路径共用连接。
- 页面、BFF、分享页、客户讲解页和最终客户只能经案例小组业务后端访问；它们不能直连数据库，也不能绕过网关。
- 网关不是旧 Case Hub 的翻版：它不判定审核通过、不决定发布、不执行撤回，只保存案例小组后端已经决定并提交的数据与发布快照。
- 网关不可用时，案例业务返回明确的 503 / 待同步状态；不得降级为直连数据库或写核心库。

### 1.2 对旧 Case Hub 口径的替代

旧方案中的以下内容停止执行：

- LibiaoLink 内部实现案例审核、发布、撤回和案例状态机。
- LibiaoLink 对外提供案例发布、撤回、分享或客户讲解业务接口。
- LibiaoLink 建设完整 case-api / case-worker 业务后端。
- 由 LibiaoLink 的 Case Hub 服务保存案例权限、分享和业务审计。

现有 `server/src/modules/case-hub` 的 L0 骨架只作为历史技术验证，不再扩展为正式案例业务后端，也不得接入核心 `AppModule`。新的案例数据网关不是该骨架的续建，二者不得混用。

## 2. 目标与非目标

### 2.1 目标

- 案例小组拥有完整业务控制权，可独立发布和迭代其业务后端。
- 案例生产业务数据落在 LibiaoLink 托管的独立数据库中，不留在案例小组本地作为生产副本。
- 案例小组后端不接触数据库凭据和对象存储永久凭据，只通过受控数据接口读写。
- 核心市场项目管理系统的数据库、API、worker、通知、文件、权限和性能不受影响；单机部署的资源争用风险按 §10.1、§12 第 13 项单独签认。
- 案例库故障、发布、迁移、备份和恢复不影响核心系统。
- 项目主数据只读；项目 ID 使用核心原始 UUID；案例侧字段不写回核心项目表。
- 外部客户只能经案例小组公开服务读取已发布内容。

### 2.2 非目标

- 不在 LibiaoLink 内实现案例审核、发布、撤回、分享和客户讲解。
- 不提供任意 SQL、数据库代理或通用 DDL API。
- 不让案例小组直接连接核心 libiaolink 数据库。
- 不修改 projects、users、project_members、tasks、files 等核心表。
- 不把案例迁移混入 database/migrations/。
- 不把案例附件放入核心文件桶或复用核心文件表。
- 不要求核心系统为案例查询增加同步接口、后台任务、表、列、索引、视图、函数或触发器；仅允许新增最小权限只读账号。
- 不把项目补充属性写回核心 projects；需要核心项目页展示时必须另立需求。

## 3. 总体架构

```text
案例库页面 / 分享页 / 外部客户
          │
          ▼
案例小组业务后端（他们）
  ├── 作者端 API / 审核 / 发布 / 撤回
  ├── 外部发布读取 API
  ├── 用户 / 角色 / 权限 / 分享 / 会话
  └── 业务审计
          │
          ├── HTTPS / mTLS / OAuth2（只接受受控数据接口）
          ▼
LibiaoLink 案例数据网关（独立进程，不属于 core-api）
  ├── 服务认证 / Scope / 限流 / 请求日志
  ├── 项目目录只读查询（读 project_read 投影）
  ├── 案例数据 CRUD / 版本校验 / 幂等
  ├── 发布快照持久化 / 已发布版本只读接口
  └── 素材上传会话 / 短时下载票据
          │
          ├── SQL（案例数据库唯一应用侧客户端）──▶ libiaolink_case
          │                                      ├── case schema（案例业务数据）
          │                                      └── project_read schema（项目摘要投影缓存）
          └── S3 ──▶ 案例对象存储（独立桶 / 前缀）

案例小组本地库（他们）
  └── 用户、角色、权限、分享、会话、业务审计

市场项目管理系统（核心，保持不变）
  core-api / core-worker / libiaolink
          │
          └── 专用只读账号 ──▶ 项目摘要投影任务（LibiaoLink 数据面）──▶ project_read
```

核心系统与案例系统的唯一数据依赖是「项目摘要投影」。案例小组后端不访问核心数据库，也不调用核心写接口；网关 API 请求路径不访问核心数据库，项目投影任务只读核心并只向案例库写入白名单摘要。

## 4. 责任边界

| 事项 | 主责 | 说明 |
|---|---|---|
| 案例草稿、提交、审核、发布、撤回 | 案例小组 | 状态机、业务校验、权限判断均在他们的后端 |
| 案例外部读取、分享、客户讲解 | 案例小组 | 对外 API 和字段脱敏由他们实现 |
| 案例用户、角色、权限、分享、会话 | 案例小组 | 保存在他们本地库，不写入案例库 |
| 案例业务审计 | 案例小组 | 保存在他们本地库；LibiaoLink 不承担业务审计 |
| 案例数据网关 | LibiaoLink | 只做数据面：认证、Scope、版本、幂等、落库、素材通道 |
| 案例表结构定义、业务字段变更 | 案例小组 | 提出 schema / 迁移，不直接执行数据库 DDL |
| libiaolink_case 实例、迁移执行、备份、监控 | LibiaoLink | 使用独立迁移账户执行，不参与案例业务逻辑 |
| project_read 项目摘要投影 | LibiaoLink | 专用只读账号按白名单查询核心，单向写入案例库摘要表 |
| 核心项目主数据 | LibiaoLink | libiaolink.projects 等原表，保持唯一事实源 |
| 核心 API / worker / 通知 / 文件 | LibiaoLink | 不修改、不注册案例模块、不增加案例任务 |
| 案例对象存储 | LibiaoLink 托管，案例小组使用 | 独立桶或独立前缀、独立凭据；案例小组只拿上传会话和短时票据 |

约束：

- libiaolink 中不新增任何案例表、列、触发器或案例索引。
- libiaolink_case 不保存核心用户、核心权限、核心任务或核心文件。
- 项目名称、编号、经理等核心主数据不复制成可写副本；发布快照是历史冻结值，不是主数据。

- 案例小组本地库不保存项目、案例、素材的生产副本；只保存其自身用户、权限、分享、会话和业务审计。
- 项目补充属性只存 `case.project_profiles`，不写核心 `projects`；如果业务要求核心项目页显示这些值，必须另立需求并单独评审，不属于本方案。

## 6. 字段落地

### 6.1 核心只读字段

从项目摘要投影读取，案例侧不改：

- projectId：核心 `projects.id`，作为 `externalProjectId`。
- projectCode：核心项目编号。
- projectName：核心项目名称。
- customerText：核心 `projects.customer` 文本，仅供展示，不作为客户稳定主体。
- region：核心项目地区。
- projectType：核心项目类型。
- managerIds / managerNames：核心项目经理。
- status、version、updatedAt、archivedAt、deletedAt。
- sourceVersion：取核心 `projects.version`。

### 6.2 案例侧项目字段

案例小组清单中的以下字段属于案例业务数据，通过网关保存在 libiaolink_case.case，**不写回核心项目表**：

- 客户稳定键、客户显示名、客户别名、客户关系。
- 合作伙伴类型、其他合作伙伴、合作伙伴别名。
- 3PL 稳定键、显示名、别名。
- 项目成员 userKey、角色、主负责人、退出时间。
- 地区多值、国家、行业、业务场景、方案类型、可否参观等核心项目表没有的补充属性。

因此，核心 `projects.customer` 只作为旧项目文本展示；案例库的客户主体必须使用案例侧稳定键。核心项目表不新增客户主体、合作伙伴、3PL、案例角色或案例补充属性字段。

### 6.3 案例内容与状态字段

- title、summary、locale、changeSummary。
- 正文六分组、亮点、成效、方案参数。
- 每个正文内容字段的密级、客户分享、客户讲解、AI 使用、审核状态、排序。
- 状态字段由案例小组定义和写入；网关不解释状态含义、不判断流转是否合法，只校验字段类型、长度、版本和幂等。

### 6.4 素材字段

- fileId、assetId、assetVersionId、objectKey、文件名、MIME、字节数、SHA-256。
- 图片宽高、视频时长、扫描状态、预览状态、转码状态。
- 展示顺序、封面、客户 Logo、素材分类、密级。
- 文件本体写案例对象存储；数据库只存元数据和对象键。
- 素材 ID 和对象键由网关生成；案例小组不得自行拼接永久对象地址。

### 6.5 不进入案例库的数据

- 案例小组用户档案、角色、权限、分享授权、会话。
- 客户讲解访问记录。
- 案例业务审计原文和字段级变更历史。
- 核心任务、日报、问题、合同、成本、内部文件、核心权限。

这些数据按案例小组清单保留在其本地库或其业务审计系统中。

### 6.6 对字段清单落地口径的修订

- 清单 1.3 条按本设计执行：案例小组不直连数据库，只调用案例数据网关；不得把案例后端直连当作例外。
- 清单 3.3 的「项目补充属性写回 LibiaoLink」在当前零影响约束下解释为写入 `case.project_profiles`，不是写入核心 `projects`。
- `externalProjectId` 使用核心项目原始 UUID；`sourceVersion` 取项目摘要版本；`expectedVersion` 取案例记录版本。
- `Idempotency-Key`、`traceId`、`operatorUserKey` 逐次写入透传；网关记录请求元数据，业务审计仍由案例小组保存。

## 7. 数据模型基线

### 7.1 project_read 项目摘要投影（LibiaoLink 维护）

```text
libiaolink_case
  project_read.project_summary
    project_id
    project_code
    project_name
    customer_text
    region
    project_type
    manager_ids
    manager_names
    status
    source_version
    source_updated_at
    archived_at
    deleted_at
    synced_at
```

- 由 LibiaoLink 项目摘要投影任务通过专用只读账号写入；只做白名单字段的派生缓存，不复制整库。
- 案例数据网关只读。
- 只保留白名单字段，不同步任务、日报、合同、成本、人员隐私和核心文件。

### 7.2 case（案例小组定义，网关落库）

至少包含：

- case.project_profiles：案例侧项目补充属性。
- case.subjects：客户、合作伙伴、3PL 主体。
- case.subject_aliases：主体别名。
- case.project_subjects：项目与主体关系。
- case.project_members：案例项目成员与角色。
- case.cases：案例草稿、正文、状态、版本。
- case.case_reviews：审核记录。
- case.case_releases：不可变发布版本、项目快照、发布哈希。
- case.case_assets：素材元数据。
- case.case_release_assets：发布版本与素材关系。
- case.case_idempotency_keys：幂等键。
- case.case_schema_migrations：案例独立迁移记录。
- case.published_release_v：只暴露 active published release 的只读视图。

不给案例小组创建以下表：

- case.users、case.roles、case.permissions、case.shares、case.sessions：归他们本地库。
- 核心 users、projects、project_members、files 等表的副本。

### 7.3 发布版本约束

- case_releases 按 case_id + release_no 唯一。
- 同一案例最多一个 active release，使用部分唯一索引兜底。
- 发布快照保存案例 payload、项目快照、payloadHash、publishedAt。
- 发布后快照不可原地修改；撤回只改变可见状态，不删除历史版本。
- 发布快照由案例小组后端在其审核通过后提交，网关只负责持久化和不可变保护，不判断是否允许发布。

### 7.4 项目与新库关联规则

- 案例侧 `case.cases.source_project_id` 存核心 `projects.id` 原始 UUID。
- 网关在首次创建案例时只校验该 ID 存在于当前 `project_read.project_summary`；未完成投影同步的项目暂不可选，不得回退为直连核心校验。不建立跨库外键，不做跨库 JOIN。
- 项目改名、换经理、归档或软删除只更新摘要，不覆盖历史发布快照。
- 已发布案例读取使用发布时项目快照；未发布草稿使用当前摘要，并显示投影同步时间 `synced_at`。

## 8. 网关接口与操作归属

### 8.1 操作归属

以下操作全部由案例小组后端完成，LibiaoLink 不提供对应业务 API：

- 创建 / 修改草稿。
- 提交审核。
- 审核通过 / 驳回。
- 发布 / 撤回。
- 生成分享链接、客户讲解会话和授权。
- 确定字段可见范围和客户侧脱敏。

### 8.2 网关数据接口

网关按资源提供受控数据接口，路径和字段以双方冻结的 OpenAPI 为准。接口类别固定为：

- 项目目录只读：按分页或增量读取 project_read.project_summary 投影，供案例小组选择项目；返回核心原始项目 UUID。
- 案例聚合读写：按 caseId 读取、保存草稿和案例版本；写入携带 expectedVersion。
- 发布快照持久化：案例小组审核并决定发布后，写入不可变 release snapshot。
- 已发布版本只读：供案例小组公开服务读取 active published release 和发布素材。
- 素材通道：创建上传会话、完成校验、签发短时下载票据。

网关明确**不提供**：提交审核、审核通过、拒绝、发布决策、撤回决策、分享授权、客户讲解会话和客户权限判断接口。

### 8.3 写入协议

每次写入至少携带：

- `externalProjectId`：核心项目 UUID。
- `sourceVersion`：本次读取到的项目摘要版本。
- `expectedVersion`：更新案例或发布记录时的当前版本。
- `Idempotency-Key`：同一业务操作重试保持不变。
- `traceId`：双方日志串联。
- `operatorUserKey`：案例小组用户稳定键，网关只透传和记录，不解释其权限。

网关校验认证、Scope、项目存在性、版本、幂等键和字段格式；版本冲突返回 409，参数错误返回 422，未认证返回 401，无权限返回 403。网关不判断案例业务角色，也不判断审核或发布是否合法。

### 8.4 公开读取隔离

- 公网和客户侧只经过案例小组公开服务。
- 案例小组公开服务调用网关的只读 Scope；网关只返回 active published release 和其发布素材，不能返回草稿、审核记录、内部备注和未发布素材。
- 公开读取路径使用独立的只读数据库角色 `case_gateway_public_ro`；作者写入路径使用 `case_gateway_authoring_rw`，两者不共用权限。
- 字段脱敏、可见范围和分享校验仍由案例小组业务后端完成；网关和数据库视图只负责发布版本隔离。

## 9. 项目摘要投影隔离

- 不建设核心库整库只读副本，不做物理主从复制，不复制核心数据库。
- 核心侧唯一允许的运维变更是新增一个仅对项目目录白名单字段授予 SELECT 的专用账号；不新增核心表、列、索引、视图、函数、触发器或后台任务。若连该只读账号也不允许，必须改为核心主动推送项目目录，另立方案。
- LibiaoLink 项目摘要投影任务优先使用已有只读节点；没有只读节点时，使用专用只读账号读取核心主库，并按白名单字段定时/增量 `SELECT`，写入 `project_read.project_summary`。
- 只读账号只授予项目目录所需字段的查询权限；投影任务不得写核心库，不得建核心表、触发器、视图或业务函数。
- 投影任务限速、限并发、超时和失败重试；读取压力纳入核心性能基线，不得因案例流量扩容核心连接池。
- 核心不可用或投影延迟时，案例侧使用最后一次摘要并显示 `synced_at` 陈旧状态；新项目在完成同步前不可选，不得回退为直连核心或写核心库。
- 项目摘要投影任务仅属于 LibiaoLink 数据面，不属于案例业务后端；网关 API 请求路径不连接核心数据库。

## 10. 隔离、安全与运维

### 10.1 数据库隔离

- 生产 libiaolink_case 必须使用独立 PostgreSQL 实例/独立集群，不得与 libiaolink 同实例；只有一台服务器时也使用独立数据目录、端口、连接池和备份。
- 独立数据盘、独立连接池、独立备份、独立监控。
- **独立实例不等于独立服务器。** 如果物理资源只有一台服务器，只能做到数据库/进程逻辑隔离，CPU、内存、磁盘、网络和主机故障域仍共享；必须单列残余风险、做资源限额和容量门禁，不能宣称物理隔离或核心绝对零影响。
- 案例数据库不得监听公网；只允许案例数据网关、项目摘要投影任务和 LibiaoLink 运维网段访问。
- 案例小组后端所在网络不得开通 libiaolink_case 的数据库端口，也不得持有数据库账号。
- 必须启用 TLS；数据库账号定期轮换。
- 案例迁移不得写入核心 database/migrations/，使用独立 case_schema_migrations。

### 10.2 对象存储隔离

- 使用独立案例桶或独立前缀，不复用核心文件桶。
- 只有案例数据网关持有案例桶 S3 凭据；案例小组只使用上传会话和短时下载票据。
- 核心文件凭据不得下发给案例小组。
- 公开服务不持有通用对象存储凭据；短时下载由网关签发。

### 10.3 部署隔离

- 案例数据网关独立部署、独立域名或独立入口，不进入核心 NestJS 进程。
- 网关不注册进 `AppModule`，不导入核心业务模块，不共享核心连接池、worker、outbox 或通知队列。
- 案例服务故障、重启、发布和回滚不影响核心；该结论以独立服务器或通过资源限额/容量门禁为前提。
- 核心 Nginx / API / worker 不需要为案例业务加载模块。
- 若必须共用入口，只增加独立 server/location，不改核心应用路由和中间件。

### 10.4 请求治理

- 网关按案例小组客户端限流、限并发、限请求体大小，并设置超时和熔断。
- 网关请求日志记录 traceId、调用方、路由、状态码、耗时和资源 ID；不记录正文全文。
- 案例数据网关的容量和连接池独立配置；核心数据库连接池不因案例流量扩容。

## 11. 迁移、备份与回滚

- 案例小组定义业务 schema 和迁移文件；LibiaoLink 使用独立 `case_migrator` 账户执行，不向案例小组发放 DDL 凭据。
- 网关不提供任意 DDL / 任意 SQL 接口；schema 变更走迁移评审和发布流程。
- project_read 迁移由 LibiaoLink 维护，只作用于摘要投影表；不得在核心库创建对应表、视图或触发器。
- 核心迁移序列保持不变；任何案例 DDL 不得追加到 database/migrations/。
- 案例数据库独立备份和 PITR；恢复演练不涉及核心库。
- 案例对象存储独立版本控制和生命周期策略。
- 案例应用回滚不得要求回滚核心应用或核心数据库。

## 12. 不影响核心系统的验收

上线前必须全部通过：

1. **代码零变更**：core-api、core-worker、AppModule、核心模块和核心迁移无案例改动。
2. **核心数据库结构零变更**：libiaolink 无新表、无新列、无触发器、无案例索引；仅新增最小权限只读账号用于项目摘要投影。
3. **网络隔离**：案例小组网络无法连接核心主库和 libiaolink_case；只能访问案例数据网关。
4. **网关唯一客户端**：只有案例数据网关及其项目摘要投影任务持有 libiaolink_case 应用账号；案例小组无数据库凭据。
5. **网关无业务决策**：接口清单和代码检查确认不存在审核、发布决策、撤回决策、分享或客户权限判断。
6. **公开读隔离**：草稿、待审、已批准未发布、已撤回数据均不能通过公开 Scope 或 `case_gateway_public_ro` 读取。
7. **故障隔离**：停止案例数据网关、案例数据库或对象存储，核心登录、项目、任务、文件、通知和 worker 正常。
8. **负载隔离**：案例接口按预期峰值压测时，核心 API p95、错误率和数据库连接数不超出基线阈值。
9. **备份隔离**：案例库恢复演练不影响核心库，也不需要停止核心服务。
10. **迁移隔离**：空库核心迁移、schema 检查、boundaries 检查结果不变；案例迁移只在独立实例执行。
11. **项目摘要投影只读**：项目摘要通过专用只读账号按白名单投影，不产生核心写入；不建立核心业务函数、触发器或整库副本。
12. **对象存储隔离**：案例桶凭据只下发给网关；案例小组只拿上传会话和短时下载票据。
13. **单机风险已签认**：若生产只有一台服务器，必须记录资源/故障域共享的残余风险、责任人和监控阈值；没有签认不得上线，也不得对外表述为核心绝对零影响。

## 13. 实施顺序

1. 双方确认本设计与 ADR-043。
2. 冻结案例数据网关的资源接口、认证方式、Scope、错误码和字段版本。
3. 开通独立案例 PostgreSQL 实例/独立集群、数据库、角色和网络策略。
4. 建立项目摘要投影任务（专用只读账号、白名单查询、限速），不建整库副本。
5. 案例小组建立 case schema 和迁移文件；LibiaoLink 执行迁移。
6. 建设案例数据网关：项目目录投影、案例读写、发布快照、素材通道。
7. 案例小组业务后端接入网关，移除所有数据库直连配置。
8. 完成权限、公开读、故障、负载、迁移和恢复验收。
9. 案例系统独立上线；核心系统不随案例发布。

## 14. 未决项

- 案例数据网关的最终 OpenAPI 路径与字段命名，在双方联调前冻结。
- 核心侧最小权限只读账号的开通、字段授权范围与读取限速；若连该账号也不允许，需改为核心主动推送项目目录并另立方案。
- 案例小组公开服务是否缓存已发布版本；缓存只能缓存 active release，且必须支持撤回后失效。
- 案例素材扫描、转码和预览由网关 worker 还是独立媒体服务承担。
- 案例迁移的提交、评审和执行时限；不得以自服务 DDL 取代。
- 案例库备份 RPO / RTO、对象存储生命周期和历史发布版本保留期限。
- 是否具备第二台服务器；若长期只有一台，单机资源争用的风险接受人和扩容触发条件。
