# ADR-043：案例库业务后端外置与隔离数据托管

- 日期：2026-11-17
- 修订：2026-11-20 新增本地项目注册、更新与归档及 `case-data:projects:write`；PATCH 使用 `expectedVersion` 乐观锁；本地项目仅存 `libiaolink_case`，与核心投影合并为项目目录，项目编号跨来源全局唯一；核心项目摘要采用常驻 `watch` 秒级增量投影，300 秒仅作晚提交安全回看窗口。2026-11-18 项目摘要改为受控只读投影；补充发布状态机、operationId 幂等、本地 outbox、素材版本、单机资源限额；确认项目范围、审核事实源、撤回外链、经理姓名和保留策略
- 状态：草案（Proposed，C 方案）；用户已确认方向和业务口径，待非作者评审与 PR 合并；未实现、未部署
- 主责：案例小组（业务后端）；LibiaoLink 案例数据网关（数据面、独立数据库、对象存储、项目摘要投影）
- 评审：wmj、px
- 关联：[案例库隔离数据面技术设计 v1.0](../案例库隔离数据面技术设计v1.0.md)

## 问题

旧 Case Hub 方案假定由 LibiaoLink 建设 case-api / case-worker，并承担案例审核、发布、撤回、外部读取和业务审计。这与最新边界不一致：

- 案例业务操作由案例小组控制，后端也由案例小组负责。
- 案例主体业务数据（案例内容、发布快照、素材元数据等）仍要保存在 LibiaoLink 托管的数据库中，案例小组本地不保存这些数据的生产副本。
- 案例小组字段清单要求项目、案例、素材和主体只能调用受控接口，不得直连 LibiaoLink 数据库。
- 当前市场项目管理系统的数据库和后端不能受到影响，必须保证现有系统稳定运行。

因此需要重新确定控制面、数据面和核心系统之间的隔离方式。

## 决策

1. **案例小组后端是唯一业务控制面**：负责草稿、提交、审核、发布、撤回、分享、客户讲解、外部读取、用户、权限、会话和业务审计。
2. **LibiaoLink 不建设案例业务后端**：不建设审核、发布、撤回、分享、客户讲解和外部 published-cases 业务接口，不替案例小组决定状态流转。
3. **LibiaoLink 建设独立案例数据网关**：案例数据网关及其项目摘要投影任务，是案例数据库唯一的应用侧客户端，也是案例小组访问案例数据的唯一入口。
4. **案例小组不持有数据库和对象存储凭据**：案例小组后端只通过 HTTPS / mTLS / OAuth2 调用网关；不接收 libiaolink_case 账号、密码、连接串或永久 S3 凭据。
5. **网关只做数据面**：负责服务认证、Scope、项目摘要投影、案例数据落库、版本校验、幂等、`stageRelease` / `activateRelease` / `deactivateRelease` 数据动作、素材上传和短时下载；只执行案例小组已经决定的状态切换，不判断审核、发布或撤回是否合法。
6. **核心业务系统不改**：不新增核心表、不新增核心迁移、不修改 core-api / core-worker、不共享连接池、不共享 worker、不共享 outbox、不共享文件桶；核心侧仅新增最小权限只读账号用于项目摘要投影。
7. **生产使用独立 PostgreSQL 实例/独立集群**：libiaolink_case 不与 libiaolink 同实例，案例资源与核心资源独立计费和监控。
8. **项目主数据只读投影**：LibiaoLink 数据面使用专用只读账号（优先已有只读节点），按白名单字段查询核心项目并写入 `project_read.project_summary`；不建整库副本、不做物理主从复制；案例侧字段不写回核心项目表。生产链路默认常驻执行秒级 `watch`，不采用 5 分钟定时刷新；`CASE_PROJECTION_OVERLAP_SECONDS` 只是长事务安全回看窗口。
9. **项目使用核心原始 ID**：`externalProjectId` / `case.cases.source_project_id` 直接使用 `libiaolink.projects.id` 原始 UUID，不重新生成；不建立跨库外键，不做跨库 JOIN。
10. **公开读取在网关和数据库双层隔离**：案例小组公开服务使用只读 Scope；网关公开读取路径只连接只读角色，只返回 active published release，不能读取草稿、审核记录和未发布素材。
11. **案例迁移独立**：案例小组定义 schema 和迁移文件，LibiaoLink 使用独立迁移账户执行；案例 DDL 只能作用于 libiaolink_case.case，不得追加到核心 database/migrations/。
12. **发布版本采用四态状态机**：`staged / active / superseded / withdrawn`。创建发布只进入 `staged`，激活后才成为唯一 `active`，旧 active 置为 `superseded`，撤回把当前 active 置为 `withdrawn`；同一案例最多一个 active，由事务锁和部分唯一索引保证。
13. **跨系统一致性使用 operationId + 本地 outbox**：案例小组后端先在本地事务写业务决定、业务审计和 outbox，再调用网关；重试、超时和重启都复用同一 `operationId`。网关只保存幂等结果，不建设案例业务 outbox，不替案例小组决定或重试业务。
14. **发布素材绑定不可变版本**：`case_release_assets` 必须保存 `asset_version_id` / `object_version_id`；发布后不按可变对象键解析。素材替换不得改变已发布页面，缺失对象版本时拒绝激活。
15. **单机也必须做硬限额**：独立 PostgreSQL 集群、独立数据目录/端口/socket/连接池，显式限制连接数、内存、临时文件、CPU、IO 和磁盘水位；案例超限只能影响案例入口。核心只读账号使用列级授权、小连接数和只读事务，禁止 `GRANT SELECT ON ALL TABLES`。
16. **业务口径已确认**：项目目录返回全部未软删除项目并包含归档；审核记录只在案例小组本地库；撤回外链返回 404；项目经理显示名按 `users(id, display_name, updated_at)` 白名单读取；已发布版本和 staged 版本不自动清理。
17. **本地项目独立登记**：案例小组可通过 `case-data:projects:write` 在 `libiaolink_case` 注册、更新和归档不进入核心库的项目；本地项目单独存储，与核心只读投影在目录查询中合并。`PATCH /api/v1/projects/{projectId}` 使用 `expectedVersion` 防止覆盖，`status=archived` 归档并可解档。`project_summary` 的字段、单向投影职责和网关只读权限不变。项目 ID 在所有核心历史摘要与本地项目之间永久唯一；项目编号在目录可用项范围内跨来源唯一（软删除或 `source_missing_at` 的历史摘要不占编号，归档项目仍占编号）。
18. **项目摘要秒级刷新**：投影进程常驻运行 `incremental`，默认每 1000ms 一轮；健康运行时核心项目变更在秒级进入 `project_summary`。可恢复的 SQL 错误记录后继续，配置或连接故障退出并由容器 / systemd 重启。全量 `reconcile` 仅作低频兜底，不负责正常刷新。

## 发布与一致性约束

- `stageRelease` 只创建 `staged` 快照，校验 `sourceVersion` 后固化项目快照、案例 payload 哈希和素材版本；激活不重新读取核心项目，不静默刷新已审核内容。
- `activateRelease` 必须携带 `expectedActiveReleaseId`（无 active 时显式 `null`）和不透明 `approvalRef`。网关只执行技术状态切换，不验证审核结论。
- `deactivateRelease` 只撤回当前 active，保留历史快照和素材；撤回后公开外链立即失效并返回 404，内部作者 Scope 仍可读取历史。
- 所有写操作必须携带 `operationId`，网关以“调用方 + operationId”保存规范化请求哈希和结果。同 key 同请求返回首次结果，同 key 不同请求返回 409，超时重试不能换 key。
- 案例小组本地 outbox 至少区分 `pending / succeeded / failed`；网关成功但本地未确认时，重启用原 operationId 查询后收敛，不得重复发布。
- 网关只提供操作结果查询、幂等和版本冲突，不负责案例业务重试、补偿或审核记录事实源。
- 案例库不创建 `case_reviews`。审核动作、意见、结论和时间线只保存在案例小组本地库，案例库只保存 `case_releases.approval_ref` 和发布技术状态。
- 项目目录固定返回全部未软删除项目，包含归档并明确标记；不另设项目白名单。目录项来自核心只读投影或案例库本地登记，二者按项目 UUID 合并。项目经理显示名只读取 `users(id, display_name, updated_at)`。
- 本地项目由网关写入 `project_read.local_projects`，不写核心 `projects`，也不写 `project_summary`；本地项目版本从 1 起，后续可参与案例创建、项目资料和发布 staging。PATCH 仅在 `expectedVersion` 与当前 `sourceVersion` 一致时更新，并原子递增版本。
- 核心项目摘要由常驻 `watch` 秒级更新；本地项目注册直接读取 `local_projects`，写入成功后立即进入目录。不得把 300 秒重叠窗口配置成刷新周期。
- 项目编号在目录可用项范围内跨来源唯一（软删除或 `source_missing_at` 的历史摘要不占编号，归档项目仍占编号）；重复编号返回 409 `PROJECT_CODE_EXISTS`。项目 ID 在所有核心历史摘要与本地项目之间永久唯一；重复项目 ID 返回 409 `PROJECT_ID_EXISTS`。
- `active / superseded / withdrawn` 发布快照及引用素材不自动删除；`staged` 首期不做自动清理。后续启用清理必须另行审批 TTL 和引用保护规则。

## 对案例小组字段清单第 1.3 条的解释

清单要求「案例库不得直连 LibiaoLink 数据库写入，只能调用受控接口」。本决策的解释是：

- 案例小组业务后端是业务控制面，但不是数据库客户端；它调用 LibiaoLink 案例数据网关。
- 案例数据网关及其项目摘要投影任务是唯一受控接口和案例数据库客户端；页面、BFF、分享页、公开服务和最终客户不得直连数据库。
- 网关不因“托管数据”而取得业务决定权；案例小组仍然决定审核、发布和撤回。
- 若未来要求案例小组直接持有数据库凭据，必须另立 ADR 重新评审，不能作为本 ADR 的实现细节。

## 对项目字段清单的落地修订

- 项目补充属性写入 `libiaolink_case.case.project_profiles`，不写核心 `projects`；需要核心项目页展示时另立需求。
- 素材 ID、对象键和下载票据由网关生成；案例小组不保存永久对象地址。
- `operatorUserKey` 由案例小组透传，网关不解释其角色和权限；业务审计、审核记录和审核状态仍由案例小组保存。
- 项目经理显示名进入核心项目摘要和发布快照，仅用于展示；其它用户字段不读取、不保存。本地项目只保存调用方提交的项目经理 ID / 显示名快照，不查询或复制核心用户档案。
- 案例小组可在案例数据面本地注册项目；本地项目字段只进入 `libiaolink_case`，核心项目表不新增记录。

## 后果

- 旧 Case Hub 的案例业务后端、审核发布、外部读取和增量同步开发停止；现有 L0 骨架只作历史，不再扩展。
- 案例小组拥有独立发布节奏，LibiaoLink 不承担案例业务故障。
- LibiaoLink 需要提供独立案例 PostgreSQL 实例/独立集群、案例数据网关、对象存储、角色、网络策略、备份和项目摘要投影任务（专用只读账号，不复制整库）。
- 案例小组需要维护案例 schema 定义、业务后端、业务审计、公开读取权限和对象存储使用规范。
- 核心系统无需为案例发布、故障或迁移停机。
- 若案例小组后端、案例数据网关或案例数据库故障，只影响案例库，不影响核心项目系统。
- 网关成为案例数据的单点入口；必须独立扩容、限流、监控和演练，不能复用核心连接池。
- 本地项目让案例目录不再只依赖核心投影；核心项目编号若与既有本地项目冲突，跨来源唯一约束会阻止投影写入，必须先人工解决编号冲突，不能静默允许重号。
- 秒级投影要求 `projection` 作为长驻服务运行并配置自动重启；只执行一次性 `incremental` 或沿用 5 分钟定时器不满足本次实时性口径。
- 案例小组后端必须实现本地 outbox 和 operationId 重查；缺失该机制会出现超时后重复发布或本地状态与数据面不一致。
- 发布素材必须绑定对象版本；若继续按可变对象键读取，替换素材会污染历史发布。
- 单机部署下必须给案例 PostgreSQL、网关和转码进程设置硬限额；只建独立数据库但不限资源，不满足核心稳定性约束。
- 独立 PostgreSQL 实例并不等于独立服务器。若只有一台服务器，C 方案只能实现数据/进程逻辑隔离，CPU、磁盘、网络和主机故障域仍共享，必须签认残余风险并做资源限额。

## 验证

- 核心代码与核心迁移零案例改动。
- libiaolink 无案例表、无案例列、无案例触发器。
- 项目摘要只做白名单投影；核心库不存在整库副本或物理主从复制。
- 常驻 `watch` 在 250–1000ms 测试间隔下能于 5 秒内反映核心项目新增和更新，并能响应终止信号。
- 案例小组网络无法连接核心主库和 libiaolink_case；只能访问案例数据网关。
- 只有案例数据网关及其项目摘要投影任务持有 libiaolink_case 应用账号；案例小组无数据库凭据。
- 网关接口清单不存在审核、发布决策、撤回决策、分享或客户权限判断。
- 案例库不存在 `case.case_reviews`；审核记录只存在案例小组本地库。公开只读路径无法读取草稿、内部备注和未发布素材。
- 案例库峰值压测时核心 API p95、错误率和数据库连接数不超基线。
- 停止案例数据网关、案例数据库或对象存储，核心系统正常。
- 案例库独立恢复演练不影响核心库。
- 若只有一台服务器，单机资源与故障域共享风险已记录，资源限额、监控阈值和扩容触发条件已验收。
- `staged` release 对外不可见；并发激活只产生一个 active；撤回后 active 置为 withdrawn。
- 同一 operationId 重复调用不产生第二次变化；同 key 不同请求返回 409；超时重查后不重复发布。
- 网关成功、响应丢失、案例小组重启后，outbox 用原 operationId 收敛为 succeeded，不产生重复 release。
- 已发布素材替换后仍读取旧 object_version_id；staged / active / superseded / withdrawn 引用的对象删除被拒绝，已发布版本和 staged 版本不自动清理。
- 案例 PostgreSQL 连接数、内存、临时文件、CPU/IO 和磁盘水位限额生效；超限只影响案例入口。
- `case_project_ro` 只能读取项目白名单列和 `users(id, display_name, updated_at)`；写、DDL、其它用户字段读取均被拒绝。
- 项目目录返回全部未软删除项目并包含归档；软删除和 source_missing_at 项目不可新建案例；撤回外链返回 404；经理姓名仅按三个用户字段读取。
- 本地项目注册、更新和归档需要 `case-data:projects:write`；结果只出现在 `libiaolink_case` 的合并目录中，核心 `projects` 与 `project_summary` 行数不变。
- 目录可用项的项目编号跨来源重复时返回 409；项目 ID 在所有历史摘要与本地项目间重复时返回 409。源缺失核心项目带同号重新出现会阻止投影并保留冲突，必须人工处理；本地项目可直接用于创建案例和发布 staging。
